# JPA 연관 매핑 리뷰 가이드

이 문서는 JPA 연관 매핑의 범위와 방식을 코드 리뷰 점검 항목으로 정리한 가이드다.
엔티티의 연관 필드와 `fetch`, `cascade` 설정이 추가되거나 변경되는 PR에 적용한다.

기준 스택은 Java, Spring Data JPA, MySQL 8.4다.

원칙 하나에서 전부 따라 나온다. **각 도메인은 자기 애그리거트(함께 바뀌어야 하는 데이터 묶음)만
직접 읽고 쓴다. 다른 도메인의 데이터는 그 도메인이 공개한 기능으로만 다룬다.**
원본은 [런치캐치_도메인_구조와_의존성_설계.md](../architecture/런치캐치_도메인_구조와_의존성_설계.md) 2.1절 규칙 1 이다.

**규칙의 서술과 코드 예시는 [jpa-association-rationale.md](./jpa-association-rationale.md)에 있다.**
이 문서는 그것을 판정할 수 있는 질문으로만 옮긴 것이다. 장 번호가 양쪽에서 같으므로 판단이
애매하면 같은 번호의 장을 보면 된다.

번호는 `AGG-`(애그리거트)를 쓴다. 1장과 2장과 3장이 모두 애그리거트 경계 이야기다.

---

## 1. 도메인 간 연관은 ID로만 갖는다

다른 도메인 엔티티에는 연관을 걸지 않고 ID 값만 필드로 둔다.
필요한 데이터는 그 도메인 `contract`의 조회 인터페이스로 받는다.

점검 항목
* `AGG-1-01` 다른 도메인 엔티티를 객체로 참조하지 않고 ID 필드로 두었는가
  ArchUnit `엔티티는_다른_도메인_엔티티를_참조하지_않는다` 가 함께 검사한다.
* `AGG-1-02` 다른 도메인 데이터를 그 도메인 `contract`의 조회 인터페이스로 받는가
  엔티티나 저장소를 직접 쓰면 규칙 1 위반이다. ArchUnit `도메인_내부는_같은_도메인에서만_쓴다` 가 함께 본다.
* `AGG-1-03` 여러 건을 읽을 때 ID 목록으로 한 번에 받는 메서드를 쓰는가
  건별로 부르면 호출 수가 건수만큼 늘어 도메인 경계를 넘는 N+1 이 된다.

## 2. 같은 도메인 안에서도 다른 애그리거트는 ID로 갖는다

애그리거트가 다르면 저장 시점과 트랜잭션도 다르다.

점검 항목
* `AGG-2-01` 같은 도메인이라도 애그리거트가 다르면 ID 로 갖는가
  패키지로 구분되지 않아 테스트가 잡지 못한다. 이 항목은 사람이 본다.

## 3. 객체 연관은 애그리거트 안에서만 쓴다

루트가 자식의 생명주기를 가질 때만 객체 연관을 두고, 자식은 루트를 통해서만 다룬다.

점검 항목
* `AGG-3-01` `cascade = ALL` 과 `orphanRemoval` 을 루트가 자식의 생명주기를 가질 때만 썼는가
* `AGG-3-02` 자식을 루트를 통해서만 추가하고 삭제하는가
  자식 저장소를 직접 불러 넣으면 루트가 모르는 상태 변화가 생긴다.
* `AGG-3-03` 저장소를 애그리거트 루트에만 두었는가
* `AGG-3-04` 따로 식별할 필요가 없는 값을 엔티티 대신 `@Embedded` 나 `@ElementCollection` 으로 두었는가

## 4. 연관 매핑 세부 규칙

점검 항목
* `AGG-4-01` `@ManyToOne` 과 `@OneToOne` 에 `fetch = FetchType.LAZY` 를 명시했는가
  기본값이 EAGER 라 원치 않는 조인과 N+1 이 생긴다.
* `AGG-4-02` 양방향 연관을 꼭 필요한 자리에만 두었고, 주인이 FK 가 있는 쪽인가
  양쪽을 맞추는 코드가 늘고 `toString` 과 JSON 직렬화에서 순환이 생긴다.
* `AGG-4-03` `@ManyToMany` 를 쓰지 않고 연결 엔티티를 직접 두었는가
  중간 테이블에 컬럼을 더할 수 없다.
* `AGG-4-04` `cascade` 가 애그리거트 경계를 넘지 않는가
  경계를 넘는 cascade 는 남의 애그리거트를 대신 저장하거나 지운다.
* `AGG-4-05` `contract` 의 record 와 이벤트 페이로드에 엔티티를 싣지 않았는가
  받는 쪽이 남의 `entity` 패키지를 import 하게 된다. ArchUnit `contract는_entity와_repository를_참조하지_않는다` 가 contract 쪽을 검사한다.

## 5. 테스트로 지키는 것

1장은 ArchUnit `엔티티는_다른_도메인_엔티티를_참조하지_않는다` 가 지킨다.
4장의 일부도 필드 규칙으로 더할 수 있다. 근거 문서 5장에 그 코드가 있다.

아직 `ArchitectureTest` 에 넣지 않았다. 그 클래스의 규칙 목록은 설계 문서 1.5절과 2.5절이 소유하므로,
규칙을 더할 때는 그 목록도 함께 고친다. 한쪽만 고치면 문서와 테스트가 어긋난다.

2장과 3장(애그리거트 경계)은 패키지로 구분되지 않아 테스트로 잡기 어렵다. 코드 리뷰에서 본다.
