# 점주 상태 조회

점주 상태 원본은 `owner.status`다. JWT와 공통 인증 객체에는 점주 상태를 저장하지 않는다.

다른 도메인은 `owner.contract.OwnerStatusQuery`를 사용한다. `findStatus`는 Redis를 먼저 조회하고, 캐시 미스 또는 Redis 장애 시 DB에서 상태 컬럼만 조회한다. 존재하지 않는 점주는 빈 Optional을 반환하며, DB 장애는 호출자에게 전파한다. 일반 조회 결과는 `ownerStatus:{ownerId}`에 저장하고 `owner.status-cache.ttl-seconds`로 TTL을 설정한다. 기본값 30초는 조정 가능한 초기값이며 성능 및 최신성 요구에 맞춰 변경한다.

`findCurrentStatus`는 캐시를 우회한다. 즉시 제한이 필요한 중요한 작업에서 사용한다. 트랜잭션 중 `findStatus`도 DB를 조회하며 미커밋 상태를 캐시에 저장하지 않는다. 트랜잭션 격리 수준에 따른 스냅샷과 동시 상태 변경까지 이 조회만으로 직렬화하지는 않는다.

현재 상태 변경 서비스는 없다. 정지, 탈퇴, 온보딩 완료 기능을 추가할 때 DB 상태를 변경하는 트랜잭션 안에서 `OwnerStatusService.invalidateAfterCommit(ownerId)`를 호출해야 한다. 롤백 시 캐시는 유지하고 커밋 성공 후 삭제한다. 삭제 실패 및 조회와 삭제의 경합에서는 TTL까지 이전 상태가 남을 수 있다. 로그인 때만 캐시를 채우는 방식은 사용하지 않는다.

로그인은 기존처럼 DB의 점주 상태와 비밀번호를 확인한다. 조회 계약 자체는 접근 허용 정책을 결정하지 않으며 각 기능에서 반환된 상태에 맞는 정책을 적용해야 한다.
