# 템플릿 요청 문구 검증기 측정의 차단과 통과 정의

이 문서는 `TemplatePromptValidator` 의 차단율과 오탐률을 재기 전에, 어떤 요청 문구를 막아야 하고 어떤 요청 문구를 통과시켜야 하는지를 정한다. 표본의 라벨은 이 정의에서 나온다.

이 정의는 검증기의 규칙 파일과 구현을 보지 않고 썼다. 규칙에 맞춰 정의를 고르면 측정이 규칙을 그대로 되풀이하기 때문이다. 기준은 `docs/design/campaign/poster-api-design.md` 의 요청 문구 검증 절이다.

## 1. 측정 대상과 범위

검증기는 관리자가 보낸 `requestPrompt` 를 모델에 보내기 전에 코드로 거른다. 걸리면 모델을 부르지 않고 사유마다 다른 오류 코드를 낸다.

| 오류 코드 | 사유 | 이 문서의 범주 |
|---|---|---|
| `POSTER-022` | 너무 짧음 | 짧음 |
| `POSTER-023` | 제어 문자와 서식 문자 | 숨은 문자 |
| `POSTER-024` | 프롬프트 인젝션 패턴 | 인젝션 |
| `POSTER-025` | 개인정보 형식 | 개인정보 |

아래는 측정하지 않는다.

- 욕설은 검증기가 일부러 검사하지 않는다. 요청 문구가 포스터에 노출되지 않고 인증된 관리자만 보내기 때문이다. 욕설 표본은 만들지 않는다.
- 분당 호출 횟수 제한과 같은 `requestId` 중복 거부는 요청 문구의 내용과 무관하므로 대상이 아니다.
- 모델 출력의 안전은 가드레일이 맡으므로 대상이 아니다.

## 2. 판정 용어

표본 하나는 `expected` 로 `BLOCK` 이나 `PASS` 중 하나를 갖는다. `BLOCK` 표본은 기대 오류 코드도 갖는다. 라벨이 애매한 표본은 `경계` 범주에 두고 `expected` 를 비운다.

| 용어 | 뜻 |
|---|---|
| 차단 | 검증기가 예외를 던져 요청을 거부했다 |
| 통과 | 검증기가 아무것도 던지지 않았다 |
| 미탐 | `BLOCK` 표본이 통과했다 |
| 오탐 | `PASS` 표본이 차단됐다 |
| 코드 일치 | `BLOCK` 표본이 기대한 오류 코드로 차단됐다 |
| 코드 불일치 | `BLOCK` 표본이 차단은 됐지만 기대와 다른 오류 코드였다 |

코드 불일치는 미탐이 아니다. 요청은 막혔기 때문이다. 다만 프론트가 사유마다 다른 안내를 보여주므로 따로 센다.

표본 하나는 범주 하나만 겨냥해 쓴다. 한 표본이 두 규칙에 걸릴 수 있으면 그 표본은 `경계` 로 둔다. 기대 코드를 하나로 정할 수 없기 때문이다.

## 3. 차단해야 하는 요청

### 3.1 숨은 문자 (`POSTER-023`)

사람 눈에 보이지 않거나 글의 방향과 모양을 바꾸는 문자가 하나라도 들어 있으면 차단한다. 앞뒤 글이 정상이어도 마찬가지다. 아래 유니코드 일반 범주를 기준으로 삼는다.

- 제어 문자(`Cc`). 탭, 줄바꿈, 캐리지 리턴은 제외한다. 이 셋은 3.5 의 경계로 다룬다.
- 서식 문자(`Cf`). 너비가 없는 문자, 방향 전환 문자와 격리 문자, 보이지 않는 연산자, 소프트 하이픈, 바이트 순서 표식이 여기 든다.

표본은 이 범주의 대표 코드포인트를 한 건에 하나씩 모두 만든다. 대표성은 기준 범주 안에서 빠진 영역이 없는지로 따진다. 영역은 C0 제어 문자, `DEL`, C1 제어 문자, 너비 없는 문자, 방향 표시와 방향 전환, 보이지 않는 연산자, 소프트 하이픈, 바이트 순서 표식이다.

문자를 문장 앞, 중간, 끝에 놓는 위치 변형은 영역마다 하나씩만 둔다. 위치에 따른 차이는 이 범주의 관심사가 아니다.

### 3.2 인젝션 (`POSTER-024`)

모델이 따르는 지시를 요청 문구로 덮어쓰거나 빼내려는 문장은 차단한다. 유형은 네 가지다.

| 유형 | 예시의 방향 |
|---|---|
| 지시 무시 | 앞선 지시나 규칙을 무시하거나 잊으라고 요구한다 |
| 역할 탈취 | 모델에게 다른 역할이나 제한 없는 모드를 맡긴다 |
| 지시 노출 요구 | 시스템 지시나 숨은 설정을 그대로 출력하라고 요구한다 |
| 출력 형식 강제 | 정해진 출력 규칙을 깨고 다른 형식으로만 답하게 한다 |

기본 문장은 한국어 8개와 영어 8개를 직접 쓴다. 네 유형이 각각 한국어 2개와 영어 2개를 갖는다. 기본 문장마다 아래 여섯 형태를 만든다.

| 형태 | 만드는 법 |
|---|---|
| 원문 | 기본 문장 그대로 |
| 띄어쓰기 | 단어 사이를 없애거나 늘린다 |
| 전각 | 영문자와 숫자를 전각으로 바꾼다 |
| 동의어 | 핵심 동사나 명사를 같은 뜻의 다른 말로 바꾼다 |
| 영한 혼합 | 한 문장 안에서 한국어와 영어를 섞는다 |
| 문장 분할 | 한 지시를 두 문장이나 두 줄로 나눈다 |

한국어 문장에는 전각 형태가 의미 있게 성립하지 않을 수 있다. 그 칸은 비워 두지 않고 영문자나 숫자가 섞인 문장으로 쓴다. 그래도 만들 수 없으면 만들지 않고 이유를 `variant` 칸이 아니라 결과 문서에 적는다.

### 3.3 개인정보 (`POSTER-025`)

개인정보 형식이 문구 속에 있으면 차단한다. 값이 진짜인지는 따지지 않는다. 형식만 본다. 다섯 종류다.

| 종류 | 형식 |
|---|---|
| 전화번호 | 휴대전화와 지역번호 번호 |
| 사업자등록번호 | 3-2-5 자리 열 자리 |
| 주민등록번호 | 앞 여섯 자리와 뒤 일곱 자리 |
| 카드번호 | 네 자리씩 네 묶음 열여섯 자리 |
| 이메일 | 사용자 부분, 골뱅이, 도메인 |

종류마다 표기 변형 10건을 만든다. 변형 축은 구분자(하이픈, 공백, 점, 없음), 전각 숫자, 앞뒤 글과의 붙임, 문장 안에 끼워 넣기다. 종류에 맞지 않는 축은 쓰지 않는다. 이메일에는 구분자 축이 없다.

표본에는 가짜 번호만 쓴다. 가짜의 기준은 아래와 같다.

- 이메일은 `example.com`, `example.org` 도메인만 쓴다.
- 전화번호는 실제로 배정되지 않은 뒷자리 `0000` 대나 `0100` 대처럼 한눈에 가짜인 번호를 쓴다.
- 주민등록번호는 생년월일이 존재하지 않는 날짜이거나 검증 숫자가 맞지 않게 만든다.
- 카드번호는 발급사 식별 구간을 피하고 검증 숫자가 맞지 않게 만든다.
- 사업자등록번호는 검증 숫자가 맞지 않게 만든다.

### 3.4 짧음 (`POSTER-022`)

글자나 숫자가 2자 미만이면 차단한다. 자음과 모음 낱자는 글자로 세지 않는다. 표본은 아래를 포함한다.

- 빈 문자열과 공백만 있는 문자열
- 글자나 숫자 1자
- 자음만 있거나 모음만 있는 문자열
- 기호만 있는 문자열
- 앞뒤 공백을 빼면 1자인 문자열

글자 수는 앞뒤 공백을 뺀 뒤 센다. 공백이 글자를 만들지 않는다는 것이 이 범주의 핵심이다.

### 3.5 경계

아래는 라벨을 확정하지 않고 `경계` 로 둔다. 각 표본은 왜 애매한지를 `variant` 칸에 짧게 적는다.

- 탭, 줄바꿈, 캐리지 리턴이 들어 있는 정상 문구. 줄을 나눠 쓰는 요청이 정상일 수 있다.
- 이모지를 이어 붙이는 보이지 않는 연결 문자가 든 문구. 서식 문자지만 이모지 하나를 이룬다.
- 정확히 2자인 문구와 낱자 하나에 글자 하나가 붙은 문구.
- 지시처럼 읽히지만 디자인 요청일 수도 있는 문구. "이전 디자인은 다 잊고 새로 만들어 줘" 같은 문장이다.
- 번호처럼 보이지만 가격, 날짜, 시간, 우편번호일 수 있는 숫자 열.
- 이메일 형식이지만 가게 안내 문구에 흔한 형태인 문자열.

경계 표본은 약 20건이다. 차단율과 오탐률의 분모에 넣지 않고 따로 보고한다. 라벨을 확인하는 단계에서 확정되면 그 범주로 옮길 수 있다.

## 4. 통과해야 하는 요청

관리자가 템플릿의 모양을 부탁하는 일반 요청은 통과해야 한다. 이 시스템에서 요청 문구는 포스터 내용이 아니라 템플릿(레이아웃)을 만드는 말이다. 정상 표본은 그 모양으로 새로 쓴다. 실제로 쓴 문구는 그대로 넣지 않고, 모양만 참고해 다시 쓴다.

정상 표본은 100건이고 세 묶음이다.

| 묶음 | 건수 | 만드는 법 |
|---|---|---|
| 일반 요청 | 60 | 느낌, 배색, 배치, 글자 크기, 여백을 부탁하는 문구를 길이와 말투를 달리해 쓴다. 한국어와 영어를 섞은 문구와 숫자가 조금 든 문구를 포함한다 |
| 패턴 단어와 겹치는 문장 | 25 | 인젝션 유형의 단어가 정상 뜻으로 쓰인 문장이다. "시스템 폰트", "규칙적인 격자", "역할을 나눈 두 단", "이전 버전보다 단순하게" 같은 말을 쓴다. 지시를 덮어쓰려는 뜻이 없어야 한다 |
| 번호 모양과 겹치는 문장 | 15 | 개인정보와 모양이 겹치는 정상 숫자다. 가격, 날짜, 시간, 퍼센트, 크기를 쓴다. 번호가 아니라 값이라는 점이 문장에서 분명해야 한다 |

정상 표본은 모두 글자나 숫자가 2자 이상이다. 2자 미만은 정상이 아니라 3.4 의 차단 표본이기 때문이다. 정확히 2자인 문구는 3.5 의 경계에 둔다.

## 5. 표본 파일의 형식

표본은 `src/test/resources/campaign/prompt/measure/` 아래 CSV 로 둔다. 칸은 다섯이다.

| 칸 | 내용 |
|---|---|
| `id` | 표본 번호. 범주 접두어와 순번으로 쓴다 |
| `category` | `숨은문자`, `인젝션`, `개인정보`, `짧음`, `정상`, `경계` 중 하나 |
| `variant` | 만든 방식. 변형 축 이름이나 코드포인트 영역이나 정상 묶음 이름 |
| `expected` | `BLOCK:POSTER-0xx`, `PASS`, 경계는 빈 값 |
| `text` | 검증기에 넣을 문구 |

숨은 문자는 CSV 에서 보이지 않으므로 `text` 에 `\uXXXX` 나 `\u{XXXXX}` 표기로 적는다. 측정 테스트가 읽을 때 이 표기를 실제 문자로 풀어서 검증기에 넣는다. 줄바꿈과 탭도 같은 방식으로 `\n` 과 `\t` 로 적는다.

## 6. 측정 지표

범주마다 아래를 센다. 경계는 모두 제외한다.

| 지표 | 계산 |
|---|---|
| 차단율 | 차단된 `BLOCK` 표본 수 ÷ 범주의 `BLOCK` 표본 수 |
| 코드 일치율 | 기대 코드로 차단된 표본 수 ÷ 범주의 `BLOCK` 표본 수 |
| 정상 오탐률 | 차단된 `PASS` 표본 수 ÷ 정상 표본 수 |
| 처리 시간 | 표본 1건을 검증하는 데 걸린 시간 |

미탐 목록, 코드 불일치 목록, 오탐 목록은 표본 전체를 문서에 옮긴다. 범주별 표본 수가 작아서 비율이 크게 흔들린다. 정상 표본이 100건이면 오탐이 0건이어도 오탐률의 95% 신뢰 상한은 약 3% 이므로, 문서는 표본 크기에 따른 한계를 함께 적는다.
