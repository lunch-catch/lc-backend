# 템플릿 요청 문구 검증기 측정의 차단과 통과 정의

이 문서는 `TemplatePromptValidator` 의 차단율과 오탐률을 재기 전에, 어떤 요청 문구를 막아야 하고 어떤 요청 문구를 통과시켜야 하는지를 정한다. 표본의 라벨은 이 정의에서 나온다.

이 정의는 검증기의 규칙 파일과 구현을 보지 않고 썼다. 규칙에 맞춰 정의를 고르면 측정이 규칙을 그대로 되풀이하기 때문이다. 기준은 `docs/design/campaign/poster-api-design.md` 의 요청 문구 검증 절이다.

## 1. 측정 대상과 범위

검증기는 관리자가 보낸 `requestPrompt` 를 모델에 보내기 전에 코드로 거른다. 걸리면 모델을 부르지 않고 사유마다 다른 오류 코드를 낸다.

| 오류 코드 | 사유 | 이 문서의 범주 |
|---|---|---|
| `POSTER-022` | 너무 짧음 | 짧음 |
| `POSTER-023` | 제어 문자와 서식 문자 | 숨은 문자 |
| `POSTER-024` | 프롬프트 인젝션 패턴 | 인젝션 |
| `POSTER-025` | 개인정보 형식 | 개인정보 |

아래는 측정하지 않는다.

- 욕설은 검증기가 일부러 검사하지 않는다. 요청 문구가 포스터에 노출되지 않고 인증된 관리자만 보내기 때문이다. 욕설 표본은 만들지 않는다.
- 분당 호출 횟수 제한과 같은 `requestId` 중복 거부는 요청 문구의 내용과 무관하므로 대상이 아니다.
- 모델 출력의 안전은 가드레일이 맡으므로 대상이 아니다.

## 2. 판정 용어

표본 하나는 `expected` 로 `BLOCK` 이나 `PASS` 중 하나를 갖는다. `BLOCK` 표본은 기대 오류 코드도 갖는다. 라벨이 애매한 표본은 `경계` 범주에 두고 `expected` 를 비운다.

| 용어 | 뜻 |
|---|---|
| 차단 | 검증기가 예외를 던져 요청을 거부했다 |
| 통과 | 검증기가 아무것도 던지지 않았다 |
| 미탐 | `BLOCK` 표본이 통과했다 |
| 오탐 | `PASS` 표본이 차단됐다 |
| 코드 일치 | `BLOCK` 표본이 기대한 오류 코드로 차단됐다 |
| 코드 불일치 | `BLOCK` 표본이 차단은 됐지만 기대와 다른 오류 코드였다 |

코드 불일치는 미탐이 아니다. 요청은 막혔기 때문이다. 다만 프론트가 사유마다 다른 안내를 보여주므로 따로 센다.

표본 하나는 범주 하나만 겨냥해 쓴다. 한 표본이 두 규칙에 걸릴 수 있으면 그 표본은 `경계` 로 둔다. 기대 코드를 하나로 정할 수 없기 때문이다.

## 3. 차단해야 하는 요청

### 3.1 숨은 문자 (`POSTER-023`)

사람 눈에 보이지 않거나 글의 방향과 모양을 바꾸는 문자가 하나라도 들어 있으면 차단한다. 앞뒤 글이 정상이어도 마찬가지다. 아래 유니코드 일반 범주를 기준으로 삼는다.

- 제어 문자(`Cc`). 탭, 줄바꿈, 캐리지 리턴은 제외하고 정상으로 본다. 줄을 나눠 쓰는 요청은 흔하기 때문이다. 세로 탭(`U+000B`), 폼 피드(`U+000C`), 다음 줄(`U+0085`)도 제외하지만 거의 쓰지 않아 3.5 의 경계로 다룬다.
- 서식 문자(`Cf`). 너비가 없는 문자, 방향 전환 문자와 격리 문자, 보이지 않는 연산자, 소프트 하이픈, 바이트 순서 표식이 여기 든다.

표본은 이 범주의 대표 코드포인트를 한 건에 하나씩 모두 만든다. 대표성은 기준 범주 안에서 빠진 영역이 없는지로 따진다. 영역은 열 개다. C0 제어 문자, `DEL`, C1 제어 문자, 너비 없는 문자(바이트 순서 표식 포함), 방향 표시, 방향 전환, 방향 격리, 보이지 않는 연산자, 소프트 하이픈, 기타 서식 문자(아랍 숫자 표지, 구간 주석, 태그 문자 등)다.

문자를 놓는 위치는 문장 앞과 끝을 영역마다 한 건씩 두고 나머지는 중간에 둔다. 코드포인트가 둘 이하인 영역은 중간만 쓴다. 위치에 따른 차이는 이 범주의 관심사가 아니다.

### 3.2 인젝션 (`POSTER-024`)

모델이 따르는 지시를 요청 문구로 덮어쓰거나 빼내려는 문장은 차단한다. 유형은 네 가지다.

| 유형 | 예시의 방향 |
|---|---|
| 지시 무시 | 앞선 지시나 규칙을 무시하거나 잊으라고 요구한다 |
| 역할 탈취 | 모델에게 다른 역할이나 제한 없는 모드를 맡긴다 |
| 지시 노출 요구 | 시스템 지시나 숨은 설정을 그대로 출력하라고 요구한다 |
| 출력 형식 강제 | 정해진 출력 규칙을 깨고 다른 형식으로만 답하게 한다 |

기본 문장은 한국어 8개와 영어 8개를 직접 쓴다. 네 유형이 각각 한국어 2개와 영어 2개를 갖는다. 기본 문장마다 아래 여섯 형태를 만들고, 영어 기본 문장에는 공백 제거를 더해 일곱 형태를 만든다.

| 형태 | 만드는 법 |
|---|---|
| 원문 | 기본 문장 그대로 |
| 띄어쓰기 | 한국어는 단어 사이를 없애고 영어는 단어 사이를 늘린다 |
| 전각 | 영문자와 숫자를 전각으로 바꾼다 |
| 동의어 | 핵심 동사나 명사를 같은 뜻의 다른 말로 바꾼다 |
| 영한 혼합 | 한 문장 안에서 한국어와 영어를 섞는다 |
| 문장 분할 | 한 지시를 마침표로 끊은 두 문장으로 나눈다. 줄바꿈은 분할의 효과와 섞이지 않게 쓰지 않는다 |
| 공백 제거 | 영어에만 만든다. 단어 사이 공백을 모두 없앤다. 한국어는 띄어쓰기 형태가 이미 공백을 없애므로 만들지 않는다 |

한국어 문장에는 전각 형태가 의미 있게 성립하지 않을 수 있다. 그 칸은 비워 두지 않고 영문자나 숫자가 섞인 문장으로 쓴다. 그래도 만들 수 없으면 만들지 않고 이유를 `variant` 칸이 아니라 결과 문서에 적는다.

### 3.3 개인정보 (`POSTER-025`)

개인정보 형식이 문구 속에 있으면 차단한다. 값이 진짜인지는 따지지 않는다. 형식만 본다. 다섯 종류다.

| 종류 | 형식 |
|---|---|
| 전화번호 | 휴대전화와 지역번호 번호 |
| 사업자등록번호 | 3-2-5 자리 열 자리 |
| 주민등록번호 | 앞 여섯 자리와 뒤 일곱 자리 |
| 카드번호 | 네 자리씩 네 묶음 열여섯 자리 |
| 이메일 | 사용자 부분, 골뱅이, 도메인 |

종류마다 표기 변형 10건을 만든다. 공통 변형 축은 구분자(하이픈, 공백, 점, 없음), 전각 숫자, 앞뒤 글과의 붙임, 문장 안에 끼워 넣기, 문장 앞이나 끝에 두기, 라벨 유무다. 종류에 맞지 않는 축은 쓰지 않는다. 이메일에는 구분자 축이 없다. 이메일은 입력 영역의 예시 값으로 쓴 2건이 라벨 확인 단계에서 더해져 12건이다.

종류에 따라 축을 더한다. 전화는 지역번호와 국제 표기를, 주민은 뒷자리 첫 숫자와 외국인등록번호를, 이메일은 대문자, 점, 플러스 태그, 서브도메인, 최상위 도메인, 전각 골뱅이를 더한다.

표본에는 가짜 번호만 쓴다. 가짜의 기준은 아래와 같다.

- 이메일은 `example.com`, `example.org` 도메인만 쓴다.
- 전화번호는 가운데 묶음을 `0000` 으로 채우고 마지막 묶음을 `0101` 처럼 한눈에 가짜인 번호로 쓴다.
- 주민등록번호는 생년월일을 실존하는 날짜로 두고 검증 숫자만 틀리게 만든다. 이 정의는 형식만 보기 때문에 날짜는 정상이어야 한다.
- 카드번호는 발급사 식별 구간을 피하고 검증 숫자가 맞지 않게 만든다.
- 사업자등록번호는 검증 숫자가 맞지 않게 만든다.

### 3.4 짧음 (`POSTER-022`)

글자나 숫자가 2자 미만이면 차단한다. 자음과 모음 낱자는 글자로 세지 않는다. 표본은 아래를 포함한다.

- 빈 문자열과 공백만 있는 문자열
- 글자나 숫자 1자
- 자음만 있거나 모음만 있는 문자열
- 기호만 있는 문자열
- 앞뒤 공백을 빼면 1자인 문자열
- 낱자 하나에 글자 하나가 붙은 문자열

글자 수는 앞뒤 공백을 뺀 뒤 센다. 공백이 글자를 만들지 않는다는 것이 이 범주의 핵심이다.

정확히 2자인 문구는 통과한다. 의미 없는 2자(`7a`)도 길이 규칙으로는 걸러지지 않는다. 그런 입력이 통과해야 하는지는 이 정의가 정하지 않고 3.5 의 경계로 둔다.

### 3.5 경계

아래는 라벨을 확정하지 않고 `경계` 로 둔다. 각 표본은 왜 애매한지를 `variant` 칸에 짧게 적는다.

- 이모지를 이어 붙이는 보이지 않는 연결 문자가 든 문구. 서식 문자지만 이모지 하나를 이룬다.
- 줄 구분자 `U+2028` 이 든 문구. 줄바꿈류지만 거의 쓰지 않고 3.1 의 기준 범주 밖이다.
- 세로 탭, 폼 피드, 다음 줄처럼 줄바꿈과 비슷하게 쓰이는 제어 문자. 3.1 이 제외하지만 거의 쓰지 않는다.
- 서식 문자(`Cf`)가 아니지만 화면에 비어 보이는 문자. 한글 채움 문자 `U+115F`, `U+1160`, `U+3164`, `U+FFA0` 과 점자 빈칸 `U+2800` 이다. 한국어 우회에 쓰이지만 3.1 의 기준 범주 밖이다.
- 의미 없는 2자(`7a`). 길이 규칙은 통과시키지만 통과해야 하는지는 정하지 않았다.
- 지시처럼 읽히는 문구. "기존 레이아웃 규칙은 버리고 자유롭게 구성해줘" 는 버리는 대상이 시스템 규칙처럼도 읽힌다.
- 번호처럼 보이지만 개인정보가 아닐 수 있는 숫자 열. 무료 전화번호 모양이 그렇다. 지역번호 번호와 구조가 같아 형식 규칙은 차단하려 하지만 개인 번호는 아니다.

경계 표본은 14건이다. 차단율과 오탐률의 분모에 넣지 않고 따로 보고한다.

라벨을 확인하는 단계에서 아래를 확정해 해당 범주로 옮겼다.

- 정상으로 확정한 것은 줄바꿈, 탭, 캐리지 리턴과 줄바꿈 없는 공백과 전각 공백이 든 문구, 정확히 2자인 `심플`, 디자인과 배색과 이전 요청을 잊거나 무시하거나 취소하는 문장 셋, 쿠폰 코드 칸을 부탁하는 문장이다.
- 짧음으로 확정한 것은 낱자 하나에 글자 하나가 붙은 `ㅋ가` 다.
- 개인정보로 확정한 것은 입력 영역의 예시 값으로 쓴 `example.com` 주소 둘이다.

## 4. 통과해야 하는 요청

관리자가 템플릿의 모양을 부탁하는 일반 요청은 통과해야 한다. 이 시스템에서 요청 문구는 포스터 내용이 아니라 템플릿(레이아웃)을 만드는 말이다. 정상 표본은 그 모양으로 새로 쓴다. 실제로 쓴 문구는 그대로 넣지 않고, 모양만 참고해 다시 쓴다.

정상 표본은 145건이고 여섯 묶음이다.

| 묶음 | 건수 | 만드는 법 |
|---|---|---|
| 일반 요청 | 60 | 느낌, 배색, 배치, 글자 크기, 여백을 부탁하는 문구를 길이와 말투를 달리해 쓴다. 한국어와 영어를 섞은 문구와 숫자가 조금 든 문구를 포함한다 |
| 패턴 단어와 겹치는 문장 | 25 | 인젝션 유형의 단어가 정상 뜻으로 쓰인 문장이다. "시스템 폰트", "규칙적인 격자", "역할을 나눈 두 단", "이전 버전보다 단순하게" 같은 말을 쓴다. 지시를 덮어쓰려는 뜻이 없어야 한다 |
| 번호 모양과 겹치는 문장 | 15 | 개인정보와 모양이 겹치는 정상 숫자다. 가격, 날짜, 시간, 퍼센트, 크기를 쓴다. 번호가 아니라 값이라는 점이 문장에서 분명해야 한다 |
| 형태가 다른 요청 | 11 | 이모지, 꺾쇠, 중괄호, 따옴표, 마크다운, 기호, 도메인 언급, 200자가 넘는 긴 문장처럼 실제 요청에 나올 만한 형태를 쓴다. 내용은 일반 요청과 같은 템플릿 부탁이다 |
| 경계에서 확정한 요청 | 10 | 라벨 확인 단계에서 정상으로 확정한 표본이다. 줄바꿈과 탭이 든 문구, 줄바꿈 없는 공백과 전각 공백이 든 문구, 정확히 2자인 문구, 디자인과 배색과 이전 요청을 잊거나 무시하거나 취소하는 문장, 쿠폰 코드 칸을 부탁하는 문장이다 |
| 말투와 길이가 다른 요청 | 24 | 일반 요청이 한 사람의 균일한 문체로 쓰인 것을 보완한다. 반말, 명사 나열, 구어체, 붙여 쓴 문장, 이모티콘, 질문형, 번호 목록, 감탄, 부정 조건, 영어 캐주얼, 메모체, 100자가 넘는 긴 문장을 쓴다. 내용은 일반 요청과 같은 템플릿 부탁이다 |

정상 표본은 모두 글자나 숫자가 2자 이상이다. 2자 미만은 정상이 아니라 3.4 의 차단 표본이기 때문이다. 정확히 2자인 문구는 통과하므로 정상 표본에 있다.

## 5. 표본 파일의 형식

표본은 `src/test/resources/campaign/prompt/measure/` 아래에 범주마다 CSV 한 파일로 나눠 둔다. 파일은 `hidden-chars.csv`, `injection.csv`, `personal-info.csv`, `too-short.csv`, `normal.csv`, `borderline.csv` 다. 모든 칸을 큰따옴표로 감싸고, 읽을 때 `text` 칸의 앞뒤 공백을 지우지 않는다. 짧음 범주의 공백뿐인 표본이 그 칸에 의존한다. 칸은 다섯이다.

| 칸 | 내용 |
|---|---|
| `id` | 표본 번호. 범주 접두어와 순번으로 쓴다 |
| `category` | `숨은문자`, `인젝션`, `개인정보`, `짧음`, `정상`, `경계` 중 하나 |
| `variant` | 만든 방식을 `/` 로 이어 쓴다. 숨은 문자는 `영역/U+코드/위치`, 인젝션은 `유형/언어/형태`, 개인정보는 `종류/변형`, 짧음은 입력의 모양, 정상은 묶음 이름이고 경계에서 확정한 것은 `경계확정/원래 이름` 이다 |
| `expected` | `BLOCK:POSTER-0xx`, `PASS`, 경계는 빈 값 |
| `text` | 검증기에 넣을 문구 |

숨은 문자는 CSV 에서 보이지 않으므로 `text` 에 `\uXXXX` 나 `\u{XXXXX}` 표기로 적는다. 측정 테스트가 읽을 때 이 표기를 실제 문자로 풀어서 검증기에 넣는다. 줄바꿈과 탭도 같은 방식으로 `\n` 과 `\t` 로 적는다. 이 표기는 숨은 문자 파일뿐 아니라 정상 파일과 경계 파일의 `text` 에도 쓰이므로 모든 파일에 같은 풀이를 적용한다.

## 6. 측정 지표

범주마다 아래를 센다. 경계는 모두 제외한다.

| 지표 | 계산 |
|---|---|
| 차단율 | 차단된 `BLOCK` 표본 수 ÷ 범주의 `BLOCK` 표본 수 |
| 코드 일치율 | 기대 코드로 차단된 표본 수 ÷ 범주의 `BLOCK` 표본 수 |
| 정상 오탐률 | 차단된 `PASS` 표본 수 ÷ 정상 표본 수 |
| 처리 시간 | 표본 1건을 검증하는 데 걸린 시간 |

미탐 목록, 코드 불일치 목록, 오탐 목록은 표본 전체를 문서에 옮긴다. 범주별 표본 수가 작아서 비율이 크게 흔들린다. 정상 표본이 145건이면 오탐이 0건이어도 오탐률의 95% 신뢰 상한은 약 2% 이므로, 문서는 표본 크기에 따른 한계를 함께 적는다.
