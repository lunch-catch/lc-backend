# 템플릿 요청 문구 검증기의 차단율과 오탐률 측정 결과

`TemplatePromptValidator` 가 관리자의 요청 문구를 얼마나 막고 얼마나 통과시키는지 표본 383건으로 쟀다. 무엇을 막아야 하고 무엇을 통과시켜야 하는지는 [측정 정의 문서](./template-prompt-validator-measure-definition.md) 가 정했고, 그 정의는 검증기의 규칙 파일을 보지 않고 썼다.

## 요약

| 범주 | 표본 수 | 차단 | 차단율 | 코드 일치율 |
|---|---|---|---|---|
| 숨은 문자 (`POSTER-023`) | 57 | 57 | 100.0% | 100.0% |
| 인젝션 (`POSTER-024`) | 104 | 38 | 36.5% | 36.5% |
| 개인정보 (`POSTER-025`) | 52 | 41 | 78.8% | 78.8% |
| 짧음 (`POSTER-022`) | 11 | 11 | 100.0% | 100.0% |

- 정상 표본 145건 중 1건이 막혔다. 정상 오탐률은 0.7% 이다.
- 막힌 표본은 모두 기대한 코드로 막혔다. 다른 코드로 막힌 표본은 없다.
- 숨은 문자와 짧음은 모두 막았다. 인젝션은 기본 문장 16개 중 9개를 원문 그대로도 통과시켰다.
- 개인정보는 형식이 정해진 번호인데도 표기가 조금 달라지면 11건을 통과시켰다.

## 1. 측정 대상과 환경

| 항목 | 내용 |
|---|---|
| 대상 | `TemplatePromptValidator` 와 `campaign/prompt/injection-patterns.txt` |
| 측정한 커밋 | `27b95a2f2` |
| 평가셋을 고정한 커밋 | `397ef3630` |
| JDK | 21.0.11 |
| 운영체제 | Windows 11 |
| 실행 방법 | `./gradlew test --tests '*TemplatePromptValidatorMeasurementTest'` |

측정 테스트는 `TemplatePromptValidatorMeasurementTest` 이고 표본은 `src/test/resources/campaign/prompt/measure/` 의 CSV 6개다. 집계는 실행할 때 `build/measure/prompt-validator-measure.md` 로 나오며 저장소에는 넣지 않는다. 이 문서의 숫자는 측정한 커밋에서만 재현된다. 이후 검증기가 바뀌면 그 커밋을 체크아웃해서 재현한다.

측정 테스트가 단언하는 것은 숨은 문자 57건이 모두 `POSTER-023` 으로 막힌다는 사실 하나다. 나머지는 결과를 기록만 한다. 미탐과 오탐은 이 문서가 다루는 측정값이지 테스트 실패가 아니기 때문이다. 운영 코드(`src/main`)는 바꾸지 않았다.

## 2. 표본 구성

| 범주 | 표본 수 | 라벨 |
|---|---|---|
| 숨은 문자 | 57 | `BLOCK:POSTER-023` |
| 인젝션 | 104 | `BLOCK:POSTER-024` |
| 개인정보 | 52 | `BLOCK:POSTER-025` |
| 짧음 | 11 | `BLOCK:POSTER-022` |
| 정상 | 145 | `PASS` |
| 경계 | 14 | 라벨 없음 |
| 합계 | 383 | |

표본마다 만든 방식은 정의 문서가 갖는다. 평가셋은 라벨을 확인한 뒤 고정했고, 고정한 뒤에는 검증기의 결과를 보고 라벨을 바꾸지 않았다. 경계 표본은 정답을 정하지 못한 표본이라 차단율과 오탐률의 분모에 넣지 않고 6절에서 반응만 적는다.

## 3. 결과

### 3.1 범주별 차단율

위 요약의 표와 같다. 차단율은 그 범주의 `BLOCK` 표본 가운데 막힌 비율이고, 코드 일치율은 기대한 코드로 막힌 비율이다. 코드 불일치가 없어서 두 값이 같다.

### 3.2 정상 표본의 오탐률

| 표본 수 | 오탐 | 오탐률 | 95% 구간 |
|---|---|---|---|
| 145 | 1 | 0.7% | 0.1% ~ 3.8% (Wilson) |

오탐 1건은 `NM-084` 다.

| id | 문구 | 막힌 코드 |
|---|---|---|
| `NM-084` | Developer mode 같은 코드 에디터 느낌의 어두운 테마 템플릿을 만들어줘 | `POSTER-024` |

인젝션 패턴 파일에 `developer mode` 구절이 단독 패턴으로 있어서, 디자인 뜻으로 쓴 문장도 걸렸다. 같은 묶음의 나머지 24건("시스템 폰트", "다크 모드", "Ignore the clutter" 등)은 통과했다.

### 3.3 검증 1건의 처리 시간

표본 383건을 워밍업 5회 뒤 20회 반복해 7,660번 쟀다.

| 평균 | 95번째 백분위 | 최대 |
|---|---|---|
| 45.7 µs | 102.2 µs | 6.8 ms |

최대값은 JIT 컴파일이나 가비지 컬렉션이 끼어든 한 번으로 보이며, 95번째 백분위가 일상적인 상한에 가깝다.

## 4. 범주별로 본 결과

### 4.1 숨은 문자

57건을 모두 막았다. 검증기는 정규화하기 전의 원문에서 제어 문자와 서식 문자를 먼저 찾고, 탭, 줄바꿈, 캐리지 리턴만 허용한다. 그래서 문장 맨 앞의 `U+0000` 과 맨 끝의 `U+0001` 도 지워지지 않고 걸렸다.

### 4.2 인젝션

기본 문장 16개에 형태를 곱한 104건 중 38건을 막았다. 기본 문장을 기준으로 보면 원문을 막은 문장이 7개이고 막지 못한 문장이 9개다.

| 형태 | 막음 / 표본 |
|---|---|
| 원문 | 7 / 16 |
| 띄어쓰기 | 7 / 16 |
| 전각 | 7 / 16 |
| 문장 분할 | 7 / 16 |
| 영한 혼합 | 4 / 16 |
| 동의어 | 3 / 16 |
| 공백 제거 (영어만) | 3 / 8 |

| 유형과 언어 | 막음 / 표본 |
|---|---|
| 지시 무시, 한국어 | 8 / 12 |
| 지시 무시, 영어 | 6 / 14 |
| 지시 노출, 한국어 | 6 / 12 |
| 지시 노출, 영어 | 12 / 14 |
| 역할 탈취, 한국어 | 0 / 12 |
| 역할 탈취, 영어 | 6 / 14 |
| 출력 형식 강제, 한국어 | 0 / 12 |
| 출력 형식 강제, 영어 | 0 / 14 |

읽어 낼 수 있는 것은 아래와 같다.

- 원문을 막은 문장 7개는 띄어쓰기, 전각, 문장 분할 변형도 모두 막았다. 정규화(전각 정리와 공백 정리)가 이 세 변형을 원문과 같은 문구로 만들기 때문이다.
- 막지 못한 쪽의 큰 부분은 변형이 아니라 원문이다. 한국어 역할 탈취, 한국어와 영어의 출력 형식 강제는 한 건도 막지 못했다.
- 원문을 막은 문장도 동의어로 바꾸면 7개 중 3개만 막았고 영한 혼합으로 섞으면 4개만 막았다.
- 영어 공백 제거는 원문을 막은 4개 중 3개를 막았다.

## 6. 경계 표본의 반응

경계 표본은 라벨을 정하지 못한 문구다. 아래는 검증기가 어떻게 반응했는지만 적은 것이고 맞고 틀림을 매기지 않는다.

| id | 문구 | 반응 | 코드 |
|---|---|---|---|
| `BD-04` | 이모지 연결 문자(가족 이모지) | 차단 | `POSTER-023` |
| `BD-05` | 이모지 연결 문자(무지개 깃발) | 차단 | `POSTER-023` |
| `BD-06` | 줄 구분자 `U+2028` | 통과 | - |
| `BD-11` | `7a` | 통과 | - |
| `BD-14` | 기존 레이아웃 규칙은 버리고 자유롭게 구성해줘 | 통과 | - |
| `BD-17` | 고객센터 080-000-0000 처럼 무료 전화 번호 모양이 … | 차단 | `POSTER-025` |
| `BD-21` | 세로 탭 `U+000B` | 차단 | `POSTER-023` |
| `BD-22` | 폼 피드 `U+000C` | 차단 | `POSTER-023` |
| `BD-23` | 다음 줄 `U+0085` | 차단 | `POSTER-023` |
| `BD-24` | 한글 초성 채움 `U+115F` | 통과 | - |
| `BD-25` | 한글 중성 채움 `U+1160` | 통과 | - |
| `BD-26` | 한글 채움 `U+3164` | 통과 | - |
| `BD-27` | 반각 한글 채움 `U+FFA0` | 통과 | - |
| `BD-28` | 점자 빈칸 `U+2800` | 통과 | - |

- 이모지에 쓰는 연결 문자가 든 문구는 서식 문자로 보고 막는다. 요청 문구에 이모지를 쓰는 관리자는 연결 문자가 든 이모지에서 막힌다.
- 한글 채움 문자와 점자 빈칸은 화면에 비어 보이지만 서식 문자가 아니어서 통과한다.
- `7a` 는 글자와 숫자가 2자라서 길이 규칙을 통과한다. 의미 없는 짧은 입력을 걸러내지 못한다.
- `080-000-0000` 은 전화번호 모양이라 개인정보 규칙에 걸린다. 개인 번호는 아니다.

## 7. 한계

- **정상 표본의 크기가 작다.** 145건 중 1건이 막혔고, 이때 오탐률의 95% 구간은 0.1% 에서 3.8% 다. 인젝션 104건과 개인정보 52건의 차단율도 각각 약 9%p, 약 11%p 의 폭을 가진다.
- **표본을 한 사람이 만들었다.** 공격 문장과 정상 문장을 같은 사람이 썼으므로 말투와 어휘가 한쪽으로 쏠렸다. 이 문서의 차단율은 이 표본에 대한 값이고, 실제 공격자나 실제 관리자의 분포를 대표하지 않는다.
- **한국어 전각 변형은 영문 토큰만 바꾼다.** 전각으로 바꿀 영문자가 한국어 문장에 `AI`, `DAN`, `HTML` 같은 토큰뿐이라, 한국어 단어를 보는 규칙에는 원문과 같은 시험이 된다.
- **번호 경계는 인위적으로 만든 표본이다.** 쿠폰 코드나 무료 전화 번호를 요청 문구에 직접 적는 일은 실제로 드물다.
- **검증기 하나만 쟀다.** 요청 DTO 단계의 입력 검증, 분당 호출 횟수 제한, 모델 출력의 가드레일과 정화는 대상이 아니다. 요청 문구 검증이 놓친 것을 뒤에서 받치는 방어는 이 문서의 숫자에 들어 있지 않다.
- **처리 시간은 한 대의 개발 PC에서 쟀다.** 운영 서버와 다르고 단일 스레드로 쟀다.
- **욕설은 측정하지 않았다.** 검증기가 일부러 검사하지 않는다.

## 8. 이 이슈에서 고치지 않은 것

이 이슈는 측정과 기록까지만 하고 운영 코드를 바꾸지 않았다. 아래는 새 이슈로 다룬다.

- 개인정보 형식의 표기 빈틈. 외국인등록번호, 국제 전화 표기, 사업자번호와 카드번호의 구분자 변형이 해당한다.
- 인젝션 패턴의 범위. 한국어 역할 탈취와 출력 형식 강제, 영어 출력 형식 강제를 어디까지 막을지와, 오탐을 늘리지 않는 조건이 해당한다.
- 길이 규칙이 걸러내지 못하는 의미 없는 짧은 입력(`7a` 같은 2자).
- 오탐 `NM-084` 와 경계 반응(이모지 연결 문자, 한글 채움 문자)에 대한 정책 판단.

수정한 뒤 같은 표본으로 다시 재면 수정에 쓴 표본이라 일반화된 개선인지 알 수 없다. 후속 이슈에서는 새로 만든 표본으로 따로 확인해야 한다.
