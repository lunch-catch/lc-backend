# v1 성능테스트

2026-10-26 AWS에서 실행한 3회의 평균으로 정리했다. MySQL에서 재고를 선택하고 발급한다. [공통 시나리오](coupon-load-test-summary.md#시나리오)를 사용했다.

## 3회 평균 결과

| 기준 | 평균 요청 수(건/초) | p95(ms) | p99(ms) | HTTP 오류(건/회) | 통계 유실(건/회) |
|---|---:|---:|---:|---:|---:|
| 3회 평균 | 500.0 | 6,929.0 | 7,202.9 | 5.7 | 953.0 |

지연시간은 성공 응답을 기준으로 한다. HTTP 오류와 통계 유실도 회당 평균 건수다. [집계 기준](coupon-load-test-summary.md#집계-기준)에서 계산 방법을 확인할 수 있다.

## Tomcat과 DB 연결

| 기준 | Tomcat 최대 쓰레드 수 | Tomcat 쓰레드 최대 활성화 수 | DB 연결 사용 최대 | DB 연결 대기 최대 |
|---|---:|---:|---:|---:|
| 3회 평균 | 200 | 200.0 | 6+2 | 194.0 |

단위는 개다. Tomcat 최대 쓰레드 수는 설정값이며, 나머지는 회차별 관측 최대값의 3회 평균이다.

DB 연결 사용은 전체 관측값에서 로깅용 2개를 구분해 `쿠폰 처리용 + 로깅용`으로 표시했다. `+2`는 로깅용 연결이다.

## DB 연결 획득과 통계 작업

| 기준 | DB 연결 획득 평균(ms) | DB 연결 획득 시간 초과(건/회) | 통계 작업 거절(건/회) |
|---|---:|---:|---:|
| 3회 평균 | 437.5 | 9.7 | 953.0 |

## 병목

DB 연결 대기에서 병목이 확인됐다. 전체 DB 연결 사용 최대는 평균 8.0개였고 연결 대기 최대는 평균 194.0개였다. Tomcat 쓰레드 최대 활성화 수도 평균 200.0개로 설정 상한에 도달했다.

DB 연결 획득에 걸린 평균 시간은 437.5ms였으며, 연결 획득 시간 초과는 회당 평균 9.7건이었다. 해당 오류 시간대의 로그에서 연결 획득 시간 초과와 트랜잭션 시작 실패도 확인했다.

통계 유실은 회당 평균 953.0건이었다. 세 회 모두 통계 작업이 거절된 건수와 일치했다.

모든 회차에서 요청 5,000건을 보냈고 HTTP 발급 성공 2,000건과 DB 발급 2,000건이 일치했다.
