# 관리자 로그인 이관 (#84)

## 기준

- fresh-market develop의 `cdd12d105556d53ad415fb47e4689f06e03c1f7d`에 있는 `AdminAuthService.login`, `AdminLoginTransactionService`, 로그인 DTO와 컨트롤러를 참고한다.
- 런치캐치 `feat/admin-registration`의 관리자 엔티티, 상태, 저장소와 BCrypt 인코더를 공통 기반으로 사용한다.
- HTTP 계약은 [auth.md](../api-spec/auth.md)의 관리자 로그인 절을 따른다.

## 이번 변경

- `POST /v1/admin/auth/tokens`만 공개한다. 재발급과 로그아웃 경로는 이번 보안 체인에서 거부한다.
- 성공은 200이며 `adminId`, `name`, `role`만 응답 본문에 담는다. Access Token과 Refresh Token 원문은 HttpOnly 쿠키로만 전달한다.
- 두 관리자 역할은 현재 역할로 JWT를 발급한다. 만료 기간과 쿠키 속성은 기존 공통 인증 모듈을 사용한다.
- 계정이 없어도 BCrypt 비교를 수행한다. 계정 없음, 비밀번호 불일치와 비활성 상태는 모두 AUTH-001로 답한다.
- BCrypt의 UTF-8 72바이트를 초과한 비밀번호도 예외나 잘린 입력의 인증 성공 없이 AUTH-001로 거부한다.
- 비밀번호 비교는 트랜잭션 밖에서 수행한다. 짧은 별도 DB 트랜잭션에서 관리자 행을 잠그고 현재 활성 상태, 관리자 역할과 비교한 비밀번호 해시를 다시 확인한다.
- Refresh Token은 해시와 만료 시각을 DB에 먼저 확정한 뒤 Redis에 저장한다. DB 저장 또는 트랜잭션 실패는 AUTH-002이며 Redis 저장 실패만으로 로그인은 실패하지 않는다.
- JWT 생성 실패, 최종 계정 검사 거부 또는 최종 DB 조회·트랜잭션 실패 시 이번 로그인에서 저장한 해시만 조건부 제거한다. 다른 로그인에서 변경한 백업은 제거하지 않으며 정리 실패도 로그인 성공으로 바꾸지 않는다.
- 로그인 요청 본문은 캐싱과 본문 로깅에서 제외하며 파싱 오류는 예외 종류만 기록한다. DTO의 문자열 출력도 비밀번호와 토큰을 마스킹한다.
- 전용 감사 필터는 본문과 토큰을 읽지 않고 시각, IP, 성공 여부와 HTTP 상태를 기록한다. 입력 오류, 429 제한과 DB 장애도 실패 시도로 기록한다.
- Redis 저장 전에 별도 트랜잭션에서 같은 관리자 행을 잠그고 DB의 현재 해시를 확인한다. 최신 토큰일 때만 캐시에 저장하며 저장이 끝날 때까지 잠금을 유지한다. 지연된 이전 로그인이 최신 캐시를 덮어쓰는 것을 막는다.
- 캐시 게시용 행 잠금은 최대 5초의 트랜잭션 안에 두며 Redis 연결과 명령 제한 시간은 각각 1초다. 최초 DB 백업 트랜잭션은 Redis I/O 전에 커밋한다.
- 최종 DB 조회·트랜잭션 실패는 AUTH-002와 503, Retry-After: 1로 거부하고 쿠키를 발급하지 않는다. 현재 DB 상태와 권한을 확인한 뒤 발생한 Redis 저장 장애만 허용한다.
- Redis 장애 때 DB와 캐시의 즉시 일치는 보장하지 않는다. 기존 정책대로 DB 백업을 기준으로 로그인은 유지하며 캐시 게시 실패를 기록한다.

## 브랜치 통합

- 이 브랜치는 develop에서 시작했으며 관리자 계정 발급 API, 서비스와 전용 체인은 포함하지 않는다.
- 계정 발급 PR이 먼저 병합되면 최신 develop을 반영하고 공유 `Admin`, `AdminRepository`의 변경을 함께 유지한다.
- 발급 PR의 `AccessTokenCutoffVerifier`, `CutoffPolicy`, 발급 체인 Order 90은 해당 PR이 소유한다. 로그인 체인은 `/v1/admin/auth/**`만 처리하므로 발급 경로와 겹치지 않는다.

## 검증 범위

- 서비스 테스트: 활성 관리자 두 역할, 더미 비교, 비활성 계정, UTF-8 길이 초과, DB/Redis 장애와 JWT 실패 보상.
- DB 작업 단위 테스트: 잠금 후 상태 및 비밀번호 변경, 토큰 백업과 조건부 제거.
- 컨트롤러와 DTO 테스트: 200 응답, 쿠키 경로와 만료 기간, 민감 정보 마스킹과 필수 입력.
- 감사 필터 테스트: 성공, 실패, 입력 오류, 요청 제한과 예외 종료 기록 및 민감 정보 미노출.
- 동시 로그인 테스트: 실제 MySQL 행 잠금과 트랜잭션을 사용해 이전 로그인 게시가 지연되어도 최신 DB 해시만 캐시에 반영되는지 검증한다. Redis 저장은 테스트 더블로 대체한다.
- 실제 Redis 네트워크 장애와 운영 로그의 1년 보존 설정은 이 테스트로 보장하지 않는다.
