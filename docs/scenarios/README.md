# 코드 기준 시나리오

LunchCatch 의 구현 코드가 실제로 하는 일을 시나리오로 모두 적은 문서다. 요구사항 명세서가 아니라 **코드가 기준**이다. 명세와 코드가 다르면 코드를 적고, 코드에 없는 동작은 적지 않는다.

쓰는 곳은 시연(2026-10-28) 데이터 작업(#741)과 화면별 확인이다. 시나리오마다 필요한 데이터 상태가 적혀 있어, 데이터는 이 문서에서 거꾸로 뽑는다.

## 표의 열

| 열 | 뜻 |
|---|---|
| ID | 앱 머리글자와 번호 |
| 시나리오 | 사용자 목표 하나 또는 분기 하나. 정상 흐름과 오류, 빈 화면, 경계 분기를 따로 적는다 |
| 단계 | 사용자가 하는 일 또는 작업이 도는 계기 |
| 화면 | 경로와 탭 |
| API | `METHOD 경로` 를 컨트롤러에 적힌 그대로 |
| 오류 코드 | 그 분기에서 나오는 `*ErrorCode` 코드 |
| 필요한 데이터 상태 | 그 분기를 만들려면 DB 와 캐시가 어떤 상태여야 하나 |
| 기대 결과 | 화면과 서버에 생기는 일 |
| 시각 조건 | 11:00 오픈처럼 시각이 정하는 조건 |

## 빠짐 확인 (2026-10-22)

뽑을 때 아래 네 목록을 코드에서 기계적으로 만들고, 모든 항목이 적어도 한 시나리오에 들어갔는지 대조했다. 각 문서 끝의 대조 절에 항목별 시나리오 ID 가 있다.

| 목록 | 개수 | 출처 | 결과 |
|---|---|---|---|
| 화면 경로 | user 19, owner 21, admin 11 (생성되는 입점 단계와 캠페인 편집 단계 포함) | 각 앱 `src/app/router.tsx` | 모두 들어감 |
| API | 124 (웹훅 2 포함) | 모든 컨트롤러 | 모두 들어감 |
| 오류 코드 | 126 | 모든 `*ErrorCode.java` | 모두 들어감. 도달하지 않는 코드는 `backend.md` 오류 코드 대조에 표시 |
| 배치와 시각 작업 | 00:00 묶음 7단계와 시각 작업 13 | 모든 `@Scheduled`, `DailyJob` | 모두 들어감 |

시나리오로 만들지 않은 것(쓰이지 않는 목업, 주석 처리된 검사, Storybook 등)은 각 문서의 대조 절 (d) 에 이유와 함께 있다.

## 갱신

코드가 바뀌면 이 문서도 바뀌어야 한다. 다시 뽑을 때는 같은 방법을 쓴다.

1. 위 네 목록을 코드에서 다시 만든다
2. 바뀐 경로, API, 오류 코드, 작업의 시나리오를 고치거나 더한다
3. 대조를 다시 돌려 빠진 항목이 없는지 본다
4. 맨 위 기준 코드 커밋을 바꾼다
