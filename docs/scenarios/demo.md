# 시연 핵심 시나리오 (2026-10-28)

[시나리오 문서](README.md) 1,222개 중 시연에서 보여 줄 흐름이다. 관리자가 템플릿을 준비하고, 점주가 그 템플릿으로 쿠폰을 내고, 회원이 피드에서 찜해 발급받아 쓰고, 점주가 사용 처리와 성과를 보고, 관리자가 전체를 관리하는 순서로 이어진다. 나머지 시나리오는 화면 확인용이다.

결함을 고치는 것을 전제로 짰다. 장면마다 고쳐야 할 결함을 [defects.md](defects.md) 의 ID 로 붙였다.

## 조건

| 항목 | 내용 |

| 시각 | 11:30 ~ 14:00 KST. 선착순 발급은 11:00 ~ 14:00, 쿠폰 사용은 캠페인 사용 시간(11:30 ~ 15:00 안)에만 된다 |
| 계정 | 관리자 `demo-admin`, 계정 발급은 `superadmin`. 점주 `demo-owner`, 잔액 부족 장면은 다른 시연 점주. 회원은 시연자 본인의 카카오 |

## 바꾸는 법

시연 흐름은 바뀔 수 있다. 이 문서가 유일한 기준이다.

1. 이 문서를 고치는 PR 을 올린다. 장면, 시나리오 ID, 고칠 결함, 위 "장면과 데이터" 표를 같이 고친다
2. 새 장면에 필요한 데이터가 있는지 본다
   - 기본 세계에 있으면 끝이다
   - 시연 계정에만 필요하면 `R__demo.sql` 을 고친다
   - 기본 세계에 없는 상태면 새 `V__` 를 더한다. 이미 적용된 `V__` 는 고치지 않는다
3. 고칠 결함이 늘거나 줄면 #762 의 결함 표와 하위 이슈를 맞춘다
4. #762 진행 기록에 무엇을 바꿨는지 한 줄 남긴다

| 마감 | 바꿀 수 있는 것 |
|---|---|
| 10-25(일) | 장면 추가와 삭제 |
| 10-26(월) | 문구, 순서 같은 작은 변경 |
| 10-27(화) | 고정. 운영을 올리고 리허설만 한다 |

운영은 매번 빈 DB 로 올라가므로 10-27 기동 전까지는 무엇을 바꿔도 깨끗하게 들어간다.
