# 쿠폰 집계 조회 계약

`coupon.contract.CouponStatsQueryService`는 분석에 쿠폰의 집계 결과를 공개한다.
SQL과 원천 데이터는 coupon이 소유하며 다른 도메인의 테이블은 읽지 않는다.
호출자는 [공개 인터페이스](../../../src/main/java/com/lunchcatch/coupon/contract/CouponStatsQueryService.java)의 record만 받는다.

## 캠페인별 일일 집계

`dailyCampaignStats(businessDate)`는 캠페인 ID 순서로 일일 집계를 반환한다.
하루는 KST의 `[00:00, 다음 날 00:00)`이다. DB의 시각도 KST로 저장하므로 같은 날짜의 `LocalDateTime` 범위를 비교한다.

| 값 | 집계 기준 |
|---|---|
| 오픈 수 | 해당 `business_date`의 `coupon_event` 행 수를 센다. 실제 오픈 이력 대신 생성된 회차 수를 사용하며 현재 상태로 제외하지 않는다 |
| 발급 수 | 해당 영업일의 회차에 속한 `member_coupon` 행 수를 센다. 사용·만료·삭제 상태도 포함한다 |
| 사용 수 | `coupon_usage_history.created_at`이 해당 KST 날짜 범위에 속한 사용 기록을 센다. 발급 회차의 영업일이 달라도 실제 사용한 날짜에 포함한다 |
| 만료 수 | 해당 영업일의 회차에 속한 회원 쿠폰 중 저장 상태가 `EXPIRED`인 행만 센다. 종료 시각이 지난 `ISSUED`나 `REMOVED`는 포함하지 않는다 |

캠페인·영업일의 유일 키가 있으므로 같은 캠페인의 오픈 수는 하루 최대 1이다.
오픈·발급·만료와 사용을 따로 묶은 뒤 `UNION ALL` 결과를 캠페인별로 합산한다. 사용 이력을 조인하여 회차·발급 수가 늘어나는 것을 막는다.
그날 회차가 없더라도 그날 사용 기록이 있는 캠페인은 반환한다. 모든 값이 없는 캠페인은 반환하지 않으며 결과가 없으면 빈 목록이다.

오픈 배치와 실제 오픈 시각 저장은 이번 계약의 선행 조건이 아니다.
만료 배치가 구현되기 전에는 저장 상태가 갱신된 쿠폰만 만료 수에 포함된다. 집계 조회는 상태를 보정하거나 이벤트를 발행하지 않는다.
`businessDate`가 null이면 `NullPointerException`을 던진다. 오늘과 미래의 조회를 막지 않으며 해당 시점에 저장된 값을 돌려준다.

## 회원별 일일 집계

`dailyMemberStats(businessDate)`는 해당 날짜에 쿠폰을 사용한 회원마다 사용 수와 확정 할인액 합을 반환한다.
입력은 날짜만 받으며 회원 ID 목록과 페이지 파라미터는 받지 않는다.
분석이 01:00에 하루 한 번 호출하므로 하루 사용 회원 수만큼의 전체 목록을 회원 ID 오름차순으로 반환한다.
사용 기록이 없는 회원은 반환하지 않으며 결과가 없으면 빈 목록이다.

영업일은 `dailyCampaignStats`의 사용 수와 같은 KST의 `[00:00, 다음 날 00:00)`이다.
`coupon_usage_history.created_at`을 날짜 범위로 제한하고 `member_coupon_id`로 회원 쿠폰과 연결하여 `member_id`별로 묶는다.
발급 회차의 영업일과 현재 쿠폰 상태로 사용 기록을 제외하지 않는다.

반환 record인 `DailyMemberCouponStats`의 값은 다음과 같다.

| 값 | 집계 기준 |
|---|---|
| `memberId` | 사용한 회원 쿠폰의 `member_id`다 |
| `usedCount` | 해당 회원의 그날 사용 이력 행 수다 |
| `discountAmount` | 해당 사용 이력의 `discount_amount` 합이다 |

사용 수와 할인액은 `long`으로 제공한다. 할인액을 계산하는 기준은 아래 회원별 누적 집계와 같다.
집계 SQL은 coupon이 소유하며 호출자에게 사용 이력 행을 공개하지 않는다.
`businessDate`가 null이면 `NullPointerException`을 던진다. 오늘과 미래도 해당 시점에 저장된 값을 반환한다.

## 회원별 누적 집계

`memberStats(memberId)`는 회원 한 명의 누적 사용 수와 확정 할인액 합을 반환한다.
회원 ID로 단건 누적 조회를 제공한다. 날짜와 페이지 파라미터는 받지 않는다.

기존 `MemberCouponRepository.findSummaryByMemberId`가 해당 회원의 쿠폰과 사용 이력을 묶은 결과를 재사용한다.
반환 record에는 그 결과의 사용 수와 할인액 합만 싣는다. 할인액은 저장된 `discount_amount`를 더하며 현재 메뉴 가격과 할인 조건으로 다시 계산하지 않는다.
할인액이 0인 사용도 포함하고 같은 금액의 사용 기록도 각각 더한다. 합계는 `long`으로 제공한다.
발급·사용 기록이 없으면 두 값이 0이다. 사용 이력의 보존 기간은 이 계약에서 바꾸지 않는다.
회원 ID가 양수가 아니면 `IllegalArgumentException`을 던진다. 회원 존재 여부와 호출자의 조회 권한은 호출자가 확인한다.

## 트랜잭션과 실패

세 메서드는 읽기 전용 트랜잭션에서 실행한다. 캐시와 쓰기 잠금, 재시도는 추가하지 않는다.
DB 조회 실패를 빈 결과나 0으로 바꾸지 않고 호출자에게 전파한다.
HTTP 엔드포인트와 분석의 저장·화면 연결은 이번 계약에 포함하지 않는다.
원천 행이 추가되거나 만료 상태가 변경되면 재조회 결과도 바뀐다. 확정된 집계의 저장과 재집계 시점은 호출자가 정한다.
캠페인별 결과는 요청한 하루의 캠페인 수만큼 나오고 회원별 일일 결과는 그날 사용한 회원 수만큼 나온다.
두 조회의 운영 규모 실행 계획과 처리량은 아직 측정하지 않았다.

## 검증

`CouponIntegrationTest`에서 공개 contract를 주입받아 실제 MySQL 집계를 확인한다.
회차의 상태·영업일과 회원을 구분하고 사용 날짜의 양 끝 경계와 합계의 32비트 초과를 검증한다.
회원별 일일 집계는 0원과 같은 할인액의 반복 사용을 포함하고 모든 날짜의 합이 회원별 누적 집계와 같은지 확인한다.
`CouponStatsQueryServiceImplTest`는 입력 검증과 결과 변환, DB 장애의 전파를 확인한다.
