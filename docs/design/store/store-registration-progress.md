# 가게 등록 진행 상태 저장 기반

## 범위

store 도메인이 진행 상태를 소유한다.
이번 변경은 내부 저장 기반이며 HTTP 조회 API와 약관 API 연동은 포함하지 않는다.
입력값은 각 단계의 기존 업무 테이블에 저장하고 진행 상태에는 점주 ID, 가게 ID, 재개 단계와 버전만 둔다.

## 단계

TERMS → STORE → BUSINESS_VERIFICATION → LOCATION → HOURS → IMAGES → MENU 순서다.
REVIEW와 COMPLETE는 저장하지 않는다.
프론트는 STORE와 BUSINESS_VERIFICATION을 같은 기본 정보 화면에 연결한다.
기본 정보 저장 후 사업자 검증에 성공하면 LOCATION으로 진행하며 검증 실패 시 BUSINESS_VERIFICATION을 유지한다.
재접속 시 BUSINESS_VERIFICATION이면 기존 가게와 기본 정보를 복원하여 재검증하며 가게를 새로 생성하지 않는다.
메뉴 저장 이후에도 재개 단계는 MENU이며 최종 등록 여부는 store.finalized를 사용한다.
따라서 MENU라는 단계 값만으로 메뉴 입력 완료나 최종 등록 가능 여부를 판단하지 않는다.
최종 등록 서비스는 약관과 모든 필수 업무 데이터를 다시 검증해야 한다.

가게 대표 이미지와 선택한 내부 이미지의 저장이 완료되면 MENU로 진행한다.
메뉴 저장은 최종 등록 확정과 구분하며 afterSave는 진행 단계만 계산한다.
조회와 화면 복원에서는 store.finalized를 먼저 확인한다.

| 저장 상태 | 화면 복원 동작 |
|---|---|
| finalized=false, resumeStep=MENU | 저장된 메뉴 입력값을 복원하고 메뉴 입력 또는 최종 등록을 이어서 진행한다 |
| finalized=true | 등록이 완료되었으므로 resumeStep과 관계없이 온보딩을 종료한다 |

메뉴 화면의 등록 완료 버튼에서 메뉴 저장과 최종 등록을 함께 처리하는 경우에도 전체 필수 조건을 다시 검증해야 한다.
최종 등록 확정이 성공한 뒤에만 클라이언트가 온보딩을 종료한다.
최종 등록 확정과 조회 API의 구현은 후속 작업이다.

## 저장 계약

- 최초 초기화는 TERMS, storeId=null, version=0이다.
- initialize는 기존 진행 상태를 초기화하지 않고 그대로 반환한다.
- 최초 초기화 호출자는 같은 트랜잭션에서 점주 행을 먼저 잠그고 계정과 ONBOARDING 상태를 확인해야 한다.
- 잠금 순서는 점주 행 → 진행 상태 행 → 단계별 데이터다.
- StoreRegistrationProgressService는 Propagation.MANDATORY로 호출자의 쓰기 트랜잭션에 참여한다.
- 단계 저장 서비스는 진행 상태 행을 먼저 잠그고 요청 버전을 확인한 뒤 입력값을 검증하고 저장해야 한다.
- completeStep은 같은 트랜잭션에서 호출하며 버전과 현재 단계를 다시 확인하고 버전을 1 증가시킨다.
- version은 JPA 자동 버전이 아니라 진행 상태 행의 비관적 쓰기 잠금 아래 명시적으로 증가시키는 요청 버전이다.
- 입력값이 같거나 MENU에 머무는 저장도 버전을 증가시킨다.
- 현재 단계의 완료만 지원하며 단계 건너뛰기와 이전 단계 수정은 거부한다.
- 기본 정보 저장 성공 시 본인 소유의 finalized=false 가게를 연결하고 BUSINESS_VERIFICATION으로 진행한다.
- 약관 단계에서는 가게가 없어야 하며 가게는 기본 정보 완료 시에만 연결한다.
- 실패 예외를 잡아 성공으로 바꾸지 않으며 입력값과 진행 상태를 함께 롤백한다.
- 객체 스토리지 업로드와 외부 사업자 검증 호출은 DB 트랜잭션 밖에서 처리한다.

이전 단계 수정과 이후 단계 무효화 정책은 해당 기능을 구현할 때 별도로 정의한다.
현재 브랜치에는 약관 API 구현이 없으며 약관 기능 연동과 진행 상태 자동 생성은 후속 작업이다.
기존 약관 동의 내역을 신규 진행 상태에 반영하는 초기화 정책도 연동 작업에서 정의해야 한다.
다른 도메인에서 호출할 때는 entity나 repository를 참조하지 않고 store.contract의 공개 계약을 추가한다.

## 내부 오류

| 코드 | 상태 | 조건 |
|---|---|---|
| STORE-001 | 409 | 요청 버전이 현재 버전과 다름 |
| STORE-002 | 409 | 완료 요청 단계가 현재 단계와 다름 |
| STORE-003 | 409 | 진행 상태 초기화 전 완료 요청 |
| STORE-004 | 403 | 본인 소유의 미확정 가게가 아닌 가게 연결 요청 |

이번 작업에서 진행 상태용 StoreErrorCode와 StoreException을 추가한다.
HTTP 경로와 요청·응답 계약은 후속 API 구현에서 정의한다.

## 브랜치 적용 기준

이슈 #249를 위해 약관 기능에 의존하지 않는 내부 기반으로 구성한다.
현재 store 도메인에는 오류 코드 구현이 없으므로 진행 상태 오류는 STORE-001부터 연속해서 부여한다.
약관 기능과 병합할 때에는 오류 코드 중복을 확인하고 명세와 테스트를 함께 조정한다.
