# store 장애 처리 설계

공통 기준은 [장애_처리_설계_가이드.md](../장애_처리_설계_가이드.md)다. 여기서는 그 기준을
그대로 따르는 대상은 적지 않고, store 도메인이 기대는 대상과 벗어난 것만 적는다.

## 이 도메인이 기대는 대상

| 유형 | 대상 |
|---|---|
| DB | MySQL(JPA, Querydsl), `store`/`store_menu`/`store_image`/`store_registration_progress` 등 |
| 외부 API | S3(`S3Presigner`, `S3Client`. presigned URL 발급과 `headObject` 확인, `#375`) |
| 캐시 | 해당 없음(이 도메인은 캐시에 기대지 않는다) |
| 애플리케이션 | 해당 없음(아직 훑지 않음) |
| 롤백 안 되는 효과 | 해당 없음(아직 훑지 않음) |

## 아직 정하지 못한 것

| 항목 | 비고 |
|---|---|
| S3 호출의 재시도 | 기본 처리는 "멱등한 연산의 재시도 가능한 오류만 재시도"다. `headObject`(읽기, 멱등)와 presign 발급(로컬 서명, 네트워크 호출 없음) 모두 지금은 재시도를 두지 않는다. S3 쪽에 재시도 인프라(`WebClient`/`RestClient`의 타임아웃·재시도 설정 같은 것)가 이 저장소에 아직 없어, `#375`는 그대로 전파하고 넘어갔다 |
| 캐시, 애플리케이션, 롤백 안 되는 효과 유형의 점검 | `#375`가 건드린 범위 밖이라 훑지 않았다 |
