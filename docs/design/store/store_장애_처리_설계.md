# store 장애 처리 설계

공통 기준은 [장애_처리_설계_가이드.md](../장애_처리_설계_가이드.md)다. 여기서는 그 기준을
그대로 따르는 대상은 적지 않고, store 도메인이 기대는 대상과 벗어난 것만 적는다.

## 이 도메인이 기대는 대상

| 유형 | 대상 |
|---|---|
| DB | MySQL(JPA, Querydsl), `store`/`store_menu`/`store_image`/`store_registration_progress` 등 |
| 외부 API | S3(`S3Presigner`, `S3Client`. presigned URL 발급과 `headObject` 확인, `#375`, `#389`) |
| 캐시 | 해당 없음(이 도메인은 캐시에 기대지 않는다) |
| 애플리케이션 | 해당 없음(아직 훑지 않음) |
| 롤백 안 되는 효과 | 해당 없음(아직 훑지 않음) |

## 벗어난 것

#788의 메뉴 조회는 DB 장애와 CDN 설정 오류에 대한 기본 처리를 바꾸지 않는다.
메뉴 데이터 오류의 반환 정책은 [조회 계약](store-query-contract.md#메뉴-조회-결과-788)이 소유한다.

## 유형별 점검

### 캐시

해당 없음. store는 캐시에 기대지 않는다.

### DB

| 시나리오 | 점검 결과 |
|---|---|
| 다운, 연결 거부 | 메뉴 조회는 기본 처리대로 예외를 전파한다. 오류 메뉴 목록이나 빈 결과로 바꾸지 않는다 |
| 슬로우 쿼리, 응답 지연 | 아직 훑지 않았다 |
| 커넥션 풀 고갈 | 아직 훑지 않았다 |
| 데드락 | 메뉴 조회는 잠금과 쓰기를 추가하지 않는다. 다른 store 기능은 아직 훑지 않았다 |
| 락 대기 초과 | 아직 훑지 않았다 |
| 제약 위반, 데이터 불일치 | 메뉴 이미지의 데이터 오류는 조회 계약에 정한 반환값으로 전달한다. DB 자체의 오류는 전파한다 |
| Primary 페일오버 | 아직 훑지 않았다 |
| 복제 지연 | 아직 훑지 않았다 |

### 외부 API

| 시나리오 | 점검 결과 |
|---|---|
| 타임아웃 | 메뉴 조회는 외부 API를 부르지 않는다. S3 업로드는 아직 훑지 않았다 |
| 5xx, 연결 끊김 | 아직 훑지 않았다 |
| 지속 장애 | 아직 훑지 않았다 |
| 인증 거부 | 아직 훑지 않았다 |
| 애매한 실패 | 아직 훑지 않았다 |

### 애플리케이션

| 시나리오 | 점검 결과 |
|---|---|
| 요청이 몰린다 | 아직 훑지 않았다 |
| 대용량 조회 | 메뉴 조회는 일괄 SQL 한 번으로 처리한다. 입력 상한과 부하 목표는 아직 정하지 않았다 |
| 배포로 서버가 내려간다 | 메뉴 조회는 읽기 전용이라 부분 저장이 남지 않는다. 다른 기능은 아직 훑지 않았다 |
| 서버가 여러 대다 | 메뉴 조회는 공유 쓰기와 잠금을 추가하지 않는다. 다른 기능은 아직 훑지 않았다 |

### 롤백 안 되는 효과

| 시나리오 | 점검 결과 |
|---|---|
| 커밋 뒤 실패 | 메뉴 조회는 외부 효과가 없다. 다른 기능은 아직 훑지 않았다 |
| 커밋 전 성공 | 메뉴 조회는 외부 효과가 없다. 다른 기능은 아직 훑지 않았다 |
| 보상 실패 | 메뉴 조회는 보상 작업이 없다. 다른 기능은 아직 훑지 않았다 |

## 아직 정하지 못한 것

| 항목 | 비고 |
|---|---|
| S3 호출의 재시도 | 기본 처리는 "멱등한 연산의 재시도 가능한 오류만 재시도"다. `headObject`(읽기, 멱등)와 presign 발급(로컬 서명, 네트워크 호출 없음) 모두 지금은 재시도를 두지 않는다. S3 쪽에 재시도 인프라(`WebClient`/`RestClient`의 타임아웃·재시도 설정 같은 것)가 이 저장소에 아직 없어, `#375`와 `#389`는 그대로 전파하고 넘어갔다 |
| 캐시, 애플리케이션, 롤백 안 되는 효과 유형의 점검 | `#375`가 건드린 범위 밖이라 훑지 않았다 |
