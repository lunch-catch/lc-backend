# store 장애 처리 설계

[공통 가이드](../장애_처리_설계_가이드.md)의 기본 처리에서 벗어난 선택과 점검 범위를 적는다.
등록 경계와 조회 계약은 [구조와 동작 설계](store_구조와_동작_설계.md), [가게 API 설계](store-api-design.md), [공개 조회 계약](store-query-contract.md)이 소유한다.

2026-10-23에 병합한 develop을 기준으로 한다. 기본 범위는 PR 작성자가 `gyudongjeong`인 기능이다.
저장·진행 상태 롤백은 #249·#147·#415·#482·#489, 조회는 #427·#453·#503·#788, 최종 등록은 #502를 대조했다. 대표 이미지 검증 보정은 #608·#627, 내부 이미지를 선택으로 처리한 보정은 #633이다.
**온보딩 5단계의 로고 업로드·교체(#588), 내부 이미지 업로드(#375), 6단계 대표 메뉴·메뉴 이미지 등록(#389)은 다른 팀원 `yongmaru789`의 구현이다.** 이 기능만 예외로 포함한다. 이슈 링크와 구현자 구분은 [구조와 동작 설계](store_구조와_동작_설계.md)의 범위 표에 모았다. #534는 문서 작성 이슈다.

## 이 도메인이 기대는 대상

| 대상 | 쓰는 곳 | 처리 |
|---|---|---|
| MySQL / JPA·JDBC·Querydsl | 가게·약관·진행 상태·영업시간·이미지·메뉴 저장과 캠페인 요약 읽기 | 기본(읽기 실패를 올리고 쓰기를 롤백한다) |
| owner의 `StoreFinalizedEvent` 동기 수신 | 최종 등록 시 `ACTIVE` 전환 | 기본(같은 트랜잭션을 롤백한다) |
| `S3Client`·`S3Presigner` | `yongmaru789`의 로고·내부·메뉴 이미지 업로드 | 벗어났다. 아래 S3 절 |
| CDN 주소 설정 | 객체 키를 URL로 변환한다 | 네트워크 호출은 없다. 이미지 데이터 오류는 조회별 계약을 따르고 정상 이미지의 CDN 설정 오류는 전파한다 |

최종 등록에는 검증된 로고가 필요하다. 조회에서는 #647의 쿠폰용 로고 `null` 임시 정책과 #788의 메뉴 오류 목록, 사용자 목록·상세의 이미지 제외 정책을 구분한다. 광고 후보의 이미지 `null`과 본인 초안의 미입력 값은 [공개 조회 계약](store-query-contract.md)의 정상 결과다.
내부 이미지는 선택 항목이므로 미검증 예약이 있어도 최종 등록을 막지 않고 `VERIFIED`만 공개한다. 최종 등록 뒤에는 남은 내부 이미지 예약의 confirm도 초안 검사에서 거부한다.

## 벗어난 것

### 조회: 이미지 데이터 오류와 저장소 장애를 구분한다

#788의 메뉴 이미지 데이터 오류는 `invalidMenuIds`로 반환한다. DB 장애와 정상 이미지의 CDN 설정 오류는 전파한다. 반환 정책은 [메뉴 조회 계약](store-query-contract.md#메뉴-조회-결과-788)이 소유한다.

사용자 목록·상세의 데이터 오류는 [HTTP 명세](../../api-spec/store-api-spec.md)를 따른다. 해당 이미지·캠페인만 제외하고 WARN 로그를 남기며 DB 장애와 정상 이미지의 CDN 설정 오류는 전파한다. 업로드 검증이나 최종 등록 조건은 완화하지 않는다.

### 외부 API: S3 업로드 예약·서명·확인

아래 업로드·메뉴 구현자는 `yongmaru789`다. 시간 제한은 공통 [S3Config](../../../src/main/java/com/launchcatch/global/config/S3Config.java)를 따른다.
서비스의 별도 재시도 반복문·회로 차단기는 없으며 SDK 재시도 정책을 재정의하지 않는다. 이를 “타임아웃·재시도가 전혀 없다”라고 설명하지 않는다.

**결정: 예약을 커밋한 뒤 서명한다.**

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 예약과 서명을 같은 DB TX에서 처리한다 | 서명 실패 시 예약을 함께 롤백한다 | 자격 증명 조회가 지연되면 DB 연결·잠금을 붙잡는다 |
| B. 예약 커밋 후 서명하고 실패 시 별도 삭제를 시도한다 | 서명을 기다리는 동안 DB 잠금을 잡지 않는다 | 삭제 실패·중단으로 예약이 남을 수 있다 |

B를 따른다. 내부 이미지·메뉴 이미지와 신규 로고의 서명 실패는 새 예약 삭제를 시도한다. 기존 로고를 교체한 경우에는 같은 행을 이미 `PENDING`으로 바꿨으므로 삭제하거나 이전 로고로 자동 복원하지 않는다. 재예약·재업로드가 필요하다.
근거는 [가게 API 설계](store-api-design.md)의 이미지·대표 메뉴 절이다. 영속 예약 정리·보상은 없으며 S4에 남긴다.

**결정: 로고·내부 이미지 확인은 진행 행 잠금 안에서 한다.**

| 선택지 | 장점 | 단점 |
|---|---|---|
| A. 잠금 아래 HEAD와 검증 저장을 수행한다 | 로고 교체·최종 등록이 검증 사이에 끼어들지 않는다 | S3 지연 동안 DB 연결과 진행 행 잠금을 점유한다 |
| B. TX 밖에서 HEAD 후 다시 잠그고 확인한다 | 외부 호출 중 DB 잠금을 반환한다 | 검사 중 예약 교체·최종 등록과의 경합을 다시 검증해야 한다 |

로고·내부 이미지 confirm은 A, 메뉴 이미지 confirm은 B다. 로고·내부 이미지의 트랜잭션 분리 필요성은 S1에 남긴다.
HEAD의 404는 `IMAGE_NOT_UPLOADED`로 바꾸고 다른 저장소 실패는 전파한다. 이미 `VERIFIED`인 같은 uploadId는 성공으로 반환하지만 교체된 이전 uploadId나 최종 등록 후 확인은 거부한다.
HEAD 성공이나 클라이언트의 PUT은 DB 롤백으로 취소되지 않는다. 검증 저장 실패로 남은 객체는 자동 삭제하지 않는다. 근거는 [가게 API 설계](store-api-design.md)의 이미지·대표 메뉴 절이다.

## 유형별 점검

### 캐시

해당 없음. store 자체의 Valkey 캐시는 없다. owner 상태 캐시 무효화는 [owner 장애 설계](../owner/owner_장애_처리_설계.md)가 소유한다.

### DB

| 시나리오 | 점검 결과 |
|---|---|
| 다운, 연결 거부(읽기·쓰기) | 해당 없음. 기본 처리(읽기 실패 전파·쓰기 롤백)를 따른다 |
| 다운, 연결 거부(복구 후 재연결) | `아직 정하지 못한 것`의 S2 |
| 슬로우 쿼리, 응답 지연 | `아직 정하지 못한 것`의 S2 |
| 커넥션 풀 고갈 | `아직 정하지 못한 것`의 S2 |
| 데드락 | `아직 정하지 못한 것`의 S3 |
| 락 대기 초과 | `아직 정하지 못한 것`의 S3 |
| 제약 위반 | 해당 없음. 기본 오류·롤백을 따른다. 지정된 약관 중복·버전 충돌만 업무 오류로 변환한다 |
| 이미지 데이터 불일치 | `벗어난 것`의 조회 절 |
| Primary 페일오버 | `아직 정하지 못한 것`의 S2 |
| 복제 지연 | 해당 없음. 가게 repository에 읽기 복제본 라우팅이 없다 |

### 외부 API

| 시나리오 | 점검 결과 |
|---|---|
| 타임아웃(현재 처리) | `벗어난 것`의 S3 절 |
| 타임아웃(지연·자격 증명 경로 검증) | `아직 정하지 못한 것`의 S1 |
| 5xx, 연결 끊김(현재 처리) | `벗어난 것`의 S3 절 |
| 5xx, 연결 끊김(SDK 반복 동작 검증) | `아직 정하지 못한 것`의 S1 |
| 지속 장애 | `아직 정하지 못한 것`의 S1 |
| 인증 거부 | `아직 정하지 못한 것`의 S1 |
| 애매한 실패 | `벗어난 것`의 S3 절 |

사업자 Mock과 카카오 위치 저장은 외부 API를 호출하지 않으므로 외부 기관 타임아웃의 대상이 아니다.

### 애플리케이션

| 시나리오 | 점검 결과 |
|---|---|
| 요청이 몰린다 | `아직 정하지 못한 것`의 S2 |
| 대용량 조회 | `아직 정하지 못한 것`의 S5 |

### 롤백 안 되는 효과

| 시나리오 | 점검 결과 |
|---|---|
| 커밋 뒤 실패 | `벗어난 것`의 S3 절 |
| 커밋 전 성공 | `벗어난 것`의 S3 절. 최종 등록 이벤트는 같은 DB TX이므로 해당하지 않는다 |
| 보상 실패 | `아직 정하지 못한 것`의 S4 |

## 아직 정하지 못한 것

#788의 메뉴 반환 계약에 별도 미결정 사항은 없다. 아래는 등록·업로드와 도메인 전체의 운영 점검 항목이다.

| ID | 남은 일 |
|---|---|
| S1 | S3 지연·5xx·권한 거부와 자격 증명 조회를 검증한다. SDK 반복 동작·회로 차단·로고와 내부 이미지 confirm의 TX 분리 필요성은 업로드 구현자 `yongmaru789`와 정한다 |
| S2 | DB 지연·풀 고갈·재연결·페일오버·복구 부하를 측정한다. 공통 연결·소켓 제한을 쿼리 실행 제한이나 복구 보장으로 읽지 않는다 |
| S3 | 해당 등록·업로드 서비스에 일반 데드락 자동 재시도는 없다. 안전한 재시도 단위와 횟수를 정해 여러 단계의 부분 재실행으로 버전이 이중 증가하지 않게 한다 |
| S4 | 남은 `PENDING`·고아 S3 객체·보상 실패의 영속 정리와 운영 책임을 정한다. 로고 교체 서명 실패는 기존 행을 `PENDING`으로 유지하며 미완료 내부 이미지는 최종 등록 뒤 확인할 수 없다. 자동 복구를 보장하지 않는다 |
| S5 | 후보 5,000개·점주 요약 100개·검색 limit 10,000 상한은 구현되어 있다. 상세·내 가게의 메뉴·이미지 응답 크기와 메모리를 측정하며 기존 테스트를 운영 용량 보장으로 설명하지 않는다 |
