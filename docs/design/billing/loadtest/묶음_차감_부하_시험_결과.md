# 묶음 차감 부하 시험 결과

대기 노출 소진 시험(drain, #1198)으로 묶음 차감을 잰 회차의 결과를 적는다. 조건과 판정 기준은 [묶음 차감 부하 시험](billing_묶음_차감_부하_시험.md)이 갖는다. 노출 API 부하와 함께 돌린 2026-11-13 회차의 결과는 그 문서 6장에 있다.

## 1. 요약

| 날짜 | 시험 | 회차 사이에 시험 행을 비웠나 | 판정 |
|---|---|---|---|
| 2026-11-16 1차 | V15 인덱스의 비용(#1255) | 비우지 않았다 | 판정하지 못했다. 같은 조건의 두 회차가 4배 벌어졌다 |
| 2026-11-16 2차 | 방향 B 의 상한(#1256) | 비우지 않았다 | 판정하지 못했다. 기준 회차 둘이 2배 벌어졌다 |
| 2026-11-16 3차 | 방향 B 의 상한(#1256) | 비웠다 | **B 가 묶음 차감 한 번을 약 40% 줄인다.** 기준 회차 셋이 1.4% 안에 모였다 |

- 회차 사이에 시험 행을 비우지 않으면 회차가 뒤로 갈수록 느려져 조건의 효과를 가를 수 없었다. 회차마다 시험 행을 비우자 같은 조건의 회차가 모였다(4장).
- V15 인덱스의 비용(#1255)은 아직 재지 않았다.

## 2. 환경과 이미지

- `member-env.sh up` 으로 띄운 환경이다. 앱 2대, 배치 2대(t3.small), RDS `db.t4g.micro`(버퍼 풀 128MB, gp3 20GB 3000 IOPS)다.
- `run.sh seed 120000` 으로 회원 120,000명과 캠페인 1,000개를 넣고, `run.sh prepare` 로 그날 예약 1,000건을 만들었다.

| 조건 | 이미지 | 무엇이 다른가 |
|---|---|---|
| 기준 | `3d039501` | develop 이다. 앱 코드는 `03f6de29` 와 같다 |
| B | `a9fcf97f` | `judgeAll` 이 `insertDeducts` 를 부르지 않는다. 병합하지 않는 시험용 커밋이다 |

- B 회차에는 판정(`deduction_result`)에 `idx_deduction_result_owner_date (owner_id, business_date, billing_status, unit_price)` 와 `idx_deduction_result_created (created_at, billing_status, unit_price)` 를 붙인다. B 에서 점주 단위 기간 합과 분석의 영업일 합이 탈 인덱스다(#1256 확인 결과 댓글). 기준 회차 앞에서는 지운다.
- 방향 A(DEDUCT 를 인덱스가 적은 별도 테이블에 쓴다)는 재지 않았다. 쓰기가 여전히 두 번이라 효과의 상한이 B 보다 낮다.

## 3. 3차 결과: 방향 B 의 상한

### 3.1 회차를 돈 방법

회차마다 아래 순서로 돌았다.

1. 그 회차의 이미지로 `run.sh switch` 한다. 앞 회차와 이미지가 같으면 건너뛴다.
2. 시험 행을 비운다. `impression_log` 와 `deduction_result` 를 TRUNCATE 한다. `point_ledger` 는 DEDUCT 가 아닌 행(CHARGE 1,000, RESERVE 1,000)만 새 테이블로 옮기고 이름을 맞바꾼다.
3. 노출, 판정, 원장 DEDUCT 가 모두 0 인지 센다. 0 이 아니면 회차를 멈춘다.
4. 판정 인덱스를 그 조건에 맞춘다.
5. dirty 페이지가 200 아래, undo history 가 1,000 아래로 내려가길 기다린다.
6. 매시 2분, 12분, 22분 ... 에 `run.sh drain <회차 이름> 100000` 을 돈다. 10분마다 도는 후보 예산 갱신과 겹치지 않게 한다.
7. 원장 DEDUCT 와 판정 BILLED 를 세어 그 이미지가 맞게 돌았는지 본다.

- 원장은 TRUNCATE 하지 않는다. 그날 예약(RESERVE)이 남아 있어야 차감이 돈다.
- 원장에는 생성 컬럼 `day_reserve_dedup_key` 가 있어 `INSERT ... SELECT *` 는 거부된다. 생성 컬럼을 뺀 컬럼 목록으로 옮긴다.
- 비우기는 회차마다 31 ~ 38초 걸렸다. 비운 직후 dirty 페이지는 0, undo history 는 30 아래여서 기다리지 않았다.
- 순서는 base1, b1, base2, b2, base3, b3 다. 측정 회차에는 프로파일러를 붙이지 않았다.

### 3.2 숫자

| 지표 | base1 | b1 | base2 | b2 | base3 | b3 |
|---|---|---|---|---|---|---|
| 이미지 | 기준 | B | 기준 | B | 기준 | B |
| `relay_deduct_avg_s` | 0.436초 | 0.260초 | 0.430초 | 0.252초 | 0.430초 | 0.273초 |
| `relay_deduct_rows_per_s` | 1,171 | 1,600 | 1,200 | 1,572 | 1,202 | 1,517 |
| 노출 10만 건을 비운 시간 | 85초 | 62초 | 85초 | 62초 | 85초 | 68초 |
| 커넥션을 쥔 평균 | 201ms | 140ms | 191ms | 142ms | 192ms | 155ms |
| 초당 커밋 | 2.58 | 3.69 | 2.62 | 3.62 | 2.58 | 3.27 |
| 회차 뒤 원장 DEDUCT | 100,000 | 0 | 100,000 | 0 | 100,000 | 0 |

### 3.3 해석

- 기준 회차 셋은 0.430 ~ 0.436초로 1.4% 안에 모였다. B 회차 셋은 0.252 ~ 0.273초로 8% 안이다. 두 조건의 차이(약 40%)가 두 흔들림보다 충분히 커서 B 의 효과로 읽는다.
- 중앙값으로 기준 0.430초, B 0.260초다. 묶음 차감 한 번이 40% 줄었다. 노출 10만 건을 비운 시간은 85초에서 62초로 27% 줄었다.
- 이 값은 B 의 상한이다. 원장에 DEDUCT 를 쓰지 않고 판정 인덱스 2개만 더한 모양이다. 정산 대사와 잔액 계산이 판정을 읽도록 바꾸는 비용은 들어 있지 않다.
- 회차마다 원장의 DEDUCT 가 0 에서 시작한다. 원장이 클수록 DEDUCT 쓰기가 느려진다면(4장), 운영 크기의 원장에서 기준 코드는 이보다 느리고 B 와의 차이는 더 벌어진다. 이 관계는 재지 않았다.
- RDS CPU 는 85초 구간에 CloudWatch 1분 점이 대부분 걸리지 않았다. 점이 하나 걸린 base3 가 19% 였다.

## 4. 1차와 2차를 판정하지 못한 까닭

1차와 2차는 회차 사이에 시험 행을 비우지 않고 회차마다 새 노출을 쌓았다. 순서를 A, B, B, A 로 두어 쌓이는 효과를 양쪽에 나누려 했다.

| 차수 | 회차 | `relay_deduct_avg_s` | 같은 조건 회차끼리의 차이 |
|---|---|---|---|
| 1차 | base1, base1b(기준을 한 번 더 돌림), drop1(V15 지움) | 0.498초, 1.92초, 3.63초 | 기준 둘이 약 4배 |
| 2차 | base1, b1, b2, base2 | 0.366초, 0.242초, 0.290초, 0.743초 | 기준 둘이 약 2배 |

- 1차는 회차를 노출 20만 건으로 돌렸다. drop1 한 회차에 `Innodb_buffer_pool_reads` 가 688,304 늘었다. 쌓인 데이터가 128MB 버퍼 풀을 넘은 것으로 본다.
- 2차는 PR #1260 을 병합한 새 환경에서 회차를 노출 10만 건으로 줄였다. 디스크 읽기는 base2 에서도 9,053회로 작았지만 기준 회차가 2배 느려졌다.
- 3차를 준비하며 원장 비우기가 실패한 채 돈 회차가 있다. 이때 노출과 판정은 비워졌고 원장 DEDUCT 만 쌓였다. 기준 회차만 0.358초에서 0.586초로 회차마다 느려졌고 디스크 읽기도 기준 회차에서만 늘었다. 같은 때 B 회차는 0.241초, 0.226초로 그대로였다. 원장에 DEDUCT 를 쓰는 것은 기준 이미지뿐이다.
- 그래서 1차와 2차의 흔들림은 커지는 원장에 DEDUCT 를 INSERT 하는 비용이 주된 원인으로 본다. 원장에는 인덱스가 13개(PK 포함) 있어 행이 늘수록 버퍼 풀에 들지 않는 페이지가 늘어난다고 추정한다. 원장 크기와 DEDUCT 시간의 관계는 따로 재지 않았다.
- 2차에서 B 회차 둘이 그보다 앞에 돈 기준 회차보다 빨랐던 것은 3차의 방향과 맞는다.
