# member 장애 처리 설계

이 문서는 회원 집계, 로그인 계정 판정, 탈퇴와 카카오 연결 해제를 훑었다. 토큰 교환과 Redis 토큰 정책의 상세 처리는 auth 설계가 갖는다.

## 이 도메인이 기대는 대상

| 대상 | 쓰는 곳 | 처리 |
|---|---|---|
| MySQL | 회원 일별 지표 COUNT와 로그인·재가입 판정 | 기본 처리에 따라 오류로 올린다. 없음과 조회 실패를 구분한다 |
| MySQL | 탈퇴 이력·회원·해제 작업 저장 | 같은 트랜잭션으로 되돌린다 |
| MySQL | 쿠폰 묶음 발급의 회원 상태 일괄 조회 | 기본 처리에 따라 빈 결과로 바꾸지 않고 오류로 올린다. 읽기 전용이라 잠금을 잡지 않는다 |
| 카카오 연결 해제 API | 탈퇴 직후 호출, 매일 03시 재시도 | 실패해도 탈퇴는 완료로 두고 재시도 큐에 남긴다. 아래 외부 API 절 |

## 벗어난 것

카카오 연결 해제는 실패를 호출자에게 올리지 않는다. 탈퇴는 이미 커밋됐고 해제는 사용자 응답과 무관하므로, 실패한 대상을 큐에 남겨 배치가 다시 시도한다.

## 유형별 점검

### 캐시

회원 일별 지표 조회는 캐시를 사용하지 않는다. 기존 member 기능의 캐시 사용은 아직 훑지 않았다.

### DB

| 시나리오 | 점검 결과 |
|---|---|
| 다운, 연결 거부 | 기본 처리에 따라 빈 값으로 바꾸지 않고 오류로 올린다 |
| 슬로우 쿼리, 응답 지연 | 공통 JDBC 소켓 타임아웃을 따른다. 별도 쿼리 타임아웃은 아직 정하지 않았다 |
| 커넥션 풀 고갈 | 공통 Hikari 풀 대기 상한을 넘으면 오류로 올린다 |
| 데드락 | 집계는 명시적 잠금이 없다. 로그인은 카카오 번호의 동시 삽입 교착을 새 트랜잭션으로 최대 세 번 판정한다 |
| 락 대기 초과 | 로그인은 잠금 실패의 재판정 한도를 적용한다. 탈퇴는 롤백하고 오류로 올린다 |
| 제약 위반, 데이터 불일치 | 탈퇴 이력 UNIQUE 위반은 전체 DB 변경을 롤백한다. 가입 UNIQUE 충돌은 현재 계정을 다시 잠가 판정한다. 다른 제약 위반은 성공으로 바꾸지 않는다 |
| Primary 페일오버 | 읽기 실패를 오류로 올리고 analytics의 재집계에 맡긴다 |
| 복제 지연 | 별도 읽기 복제본을 사용하지 않는다 |

### 외부 API

회원 일별 지표 조회는 외부 API를 부르지 않는다.

**카카오 연결 해제 재시도.** 탈퇴 트랜잭션에서 `kakao_unlink_failure`에 먼저 적재한 대상을 커밋 후 한 번 호출하고, 남은 행은 아래 배치가 다시 부른다. 먼저 적재하는 이유는 [member API 설계의 탈퇴 절](./member-api-design.md#2-탈퇴)에 있다.

| 항목 | 규약 |
| --- | --- |
| 주기 | 매일 03시(Asia/Seoul). 배치 서버가 두 대라 `batch_execution_log`의 작업 점유(`MEMBER_KAKAO_UNLINK_RETRY`)로 한 서버만 돈다 |
| 대상 | `resolved = FALSE AND processing = FALSE`인 행을 오래된 것부터 최대 100건. 행을 잠가 선점한 뒤 커밋한다 |
| 성공 | 큐 행 삭제 |
| 일시적 실패 | 선점을 해제하고 `attempt_count`를 올린다. 한도 5회에 닿으면 `resolved = TRUE`, `stop_reason = EXHAUSTED` |
| 영구 거부 | 카카오가 `400`·`404`로 답한 경우만 `resolved = TRUE`, `stop_reason = REJECTED`. `attempt_count`는 올리지 않는다 |
| 재시도하는 실패 | `401`·`403`(Admin Key 설정 문제라 고치면 성공할 요청이다), `429`(호출 한도), 5xx, 응답 없음 |
| 서킷 열림 | 선점만 해제하고 `attempt_count`는 올리지 않는다 |
| 재가입 | 성공으로 큐 행이 삭제될 때까지 보류한다. 포기한 행도 재가입을 막는다 |

최초 호출은 탈퇴 트랜잭션에서 선점한다. 배치는 큐 행의 비관 잠금 아래 선점하고 외부 호출은 커밋 뒤 수행한다. 웹훅과 재가입은 큐 행을 삭제하지 않으므로 외부 호출 중 재가입이 허용되지 않는다.

**실행 중단 복구.** processing이 TRUE인 채 프로세스가 죽거나 성공 후 DB 정리가 실패하면 행이 남고 재가입도 보류된다. TTL만으로 선점을 풀면 살아 있는 외부 호출과 다음 호출이 겹칠 수 있으므로 자동 만료하지 않는다. 운영자는 호출한 API·배치 프로세스 종료와 외부 호출 종료를 확인한 뒤 해당 작업 ID의 processing만 FALSE로 돌려 재시도한다. 연결 해제 성공을 확인하고 정리할 때도 실행 중 호출이 없음을 확인한다. REJECTED·EXHAUSTED는 성공 표시가 아니며 원인 확인 없이 삭제하지 않는다. 별도 복구 API는 추가하지 않는다.

**재가입 계정의 웹훅.** [구조와 동작 설계의 구분 한계](./member_구조와_동작_설계.md#연결-해제-웹훅의-구분-한계)에 따라 자동 탈퇴를 보류한다. member.unlink.webhook.ambiguous 카운터와 KAKAO_UNLINK_WEBHOOK_AMBIGUOUS 오류 로그로 운영 확인 대상을 남긴다. 외부 알림 시스템의 경보 연결은 이번 변경에서 검증하지 않았다.

카카오 로그인의 토큰 교환과 로그아웃 호출은 아직 훑지 않았다.

### 애플리케이션

| 시나리오 | 점검 결과 |
|---|---|
| 요청이 몰린다 | analytics의 일별 집계와 재집계만 호출한다. 별도 공개 HTTP 입구는 없다 |
| 대용량 조회 | DB가 COUNT만 반환하므로 회원 행을 메모리에 올리지 않는다 |
| 배포로 서버가 내려간다 | 집계는 재조회할 수 있다. 연결 해제 선점이 남으면 위 실행 중단 복구를 따른다 |
| 서버가 여러 대다 | 배치 실행 점유는 ops가 소유한다. 최초 호출과 배치가 겹치는 같은 큐 행은 processing 선점으로 막는다 |

### 롤백 안 되는 효과

회원 일별 지표 조회에는 트랜잭션 밖으로 나가는 효과가 없다.

탈퇴 뒤 카카오 연결 해제는 되돌릴 수 없는 외부 효과다. 그래서 탈퇴 커밋 뒤 트랜잭션 밖에서 부르고, 해제 대상은 커밋 전에 큐에 적재해 둔다.

## 아직 정하지 못한 것

- 운영 회원 수에서 COUNT 쿼리가 목표 시간을 넘길 때 적용할 인덱스와 별도 쿼리 타임아웃은 아직 정하지 않았다.
- 카카오 연결 해제 이외의 member 캐시와 외부 API 장애 처리(카카오 로그인, 로그아웃)는 다음 member 기능 변경 전에 훑는다.
