# adserving 장애 처리 설계

[장애 처리 설계 가이드](../장애_처리_설계_가이드.md)를 따른다. 기본 처리를 따르는 대상은 적지 않고
벗어난 것만 적는다. 이 판은 `GET /v1/feed`(#187)가 기대는 대상만 훑었다.

## 기대는 대상

| 대상 | 쓰는 곳 | 처리 |
|---|---|---|
| MySQL 읽기 | 후보, 스와이프 이력, 피드 필터, 그날 유효 노출 수 | 기본(오류로 올린다) |
| MySQL 쓰기 | `serve_log`, `feed_visit_daily` | 벗어남. 아래 "응답 뒤 쓰기" |
| Valkey | 요청 제한, 내려준 이력, serve 기록 | 기본(통과시키고 센다) |
| 정산 `BudgetQueryService` | 진행률 | 벗어남. 아래 "예산 조회" |
| 회원 `MemberQueryService` | 온보딩, 저장 위치, 성별과 연령대 | 기본(오류로 올린다) |

## 벗어난 것

### 예산 조회

**정산이 진행률을 주지 못하면 피드를 실패시킨다(500).** 정산은 카운터가 멈추면 대체값 없이 예외를
던지고 그 회차의 처리를 광고 서빙에 넘겼다. 정산의 카운터는 캐시지만 광고 서빙에게 그 값은 없으면
틀리는 값이다. 예산 없이 내려주면 상한에 닿은 캠페인이 과금 없이 노출된다. 카운터가 멈추면 노출
차감도 실패해서 피드만 살려 둘 이유가 없다(#187).

### 응답 뒤 쓰기

**`serve_log` 와 `feed_visit_daily` 는 실패해도 되돌리지 않고 버린다.** 응답 뒤에 대기열에서 쓰므로
되돌릴 요청이 없다. 판정과 과금에 쓰이지 않아 버려도 진단이 "기록 없음" 을 보일 뿐이다.

**대기열이 차면 기다리지 않고 버린다.** 기다리면 DB 가 느려질 때 피드 응답까지 늦어진다(#187). 크기는
10,000 이다.

**버린 행은 센다.** 지표는 `adserving.serve.log.dropped` 이고 태그는 `table`(`serve_log`,
`feed_visit_daily`)과 `reason`(`queue_full`, `write_failed`)이다. 서빙 로그 유실률(비기능 18행)을 이
지표로 잰다.

## 유형별 점검

### 캐시

| 시나리오 | 피드에서 |
|---|---|
| 캐시 다운 | 요청 제한, 실패한 요청을 창에서 빼기, 내려준 이력, serve 기록 모두 통과시키고 `adserving.feed.cache.bypass{target}` 로 센다 |
| 캐시 스탬피드 | 해당 없음. 원본에서 다시 채우는 캐시가 없다 |
| 분산 락 | 해당 없음 |
| 낡은 값 | 해당 없음. 정지나 탈퇴 판정을 캐시로 하지 않는다 |

### DB

| 시나리오 | 피드에서 |
|---|---|
| 다운, 연결 거부 | 읽기는 오류로 올린다. 응답 뒤 쓰기는 버리고 센다 |
| 슬로우 쿼리 | 공통 설정을 따른다. 유효 노출 집계가 가장 무겁다(구조와 동작 설계 11장) |
| 커넥션 풀 고갈 | 공통 설정을 따른다. 응답 뒤 쓰기는 2 스레드라 풀을 2개까지만 쓴다 |
| 데드락, 락 대기 초과 | 해당 없음. 피드는 잠그지 않는다 |
| 제약 위반 | `feed_visit_daily` 의 중복은 `INSERT IGNORE` 가 버린다. `serve_log` 의 키는 UUIDv7 이라 겹치지 않는다 |
| Primary 페일오버 | 응답 뒤 쓰기가 그 구간에 실패하면 버리고 센다 |
| 복제 지연 | 해당 없음. 복제본을 읽지 않는다 |

### 외부 API

해당 없음.

### 애플리케이션

| 시나리오 | 피드에서 |
|---|---|
| 요청이 몰린다 | 사용자마다 최근 60초 6회로 막는다 |
| 대용량 조회 | 후보는 5000m 상자 안만 읽는다. 상한은 두지 않았다 |
| 배포로 서버가 내려간다 | 대기열은 남은 쓰기를 10초까지 마치고 내려간다. 그 뒤 남은 것은 빠진다 |
| 서버가 여러 대다 | 요청 제한과 이력이 Valkey 에 있어 서버끼리 같은 값을 본다 |

### 롤백 안 되는 효과

해당 없음. 피드는 되돌릴 수 없는 외부 효과를 내지 않는다.

## 아직 정하지 못한 것

| 항목 | 막는 것 |
|---|---|
| 캐시 통과 지표의 경보 기준 | 지표만 있고 경보를 걸지 않았다. 몇 건부터 울릴지 정해야 한다 |
| 서빙 로그 유실 지표의 경보 기준 | 목표가 0.1% 미만이다(비기능 18행). 응답 카드 수 지표와 맞대는 대시보드가 없다 |
