# auth 장애 처리 설계

이 문서는 #655의 상수 통합이 의존 대상과 실패 처리에 영향을 주는지 훑은 범위를 기록한다. 인증 모듈 전체의 장애 시나리오는 아직 훑지 않았다. 기존 요청별 실패 처리는 [auth API 설계](./auth-api-design.md)가 갖는다.

## 이 도메인이 기대는 대상

| 대상 | 쓰는 곳 | 처리 |
|---|---|---|
| Valkey | RT 저장·회전·폐기 | 기존 auth API 설계의 토큰 처리 절을 따른다 |
| OAuth 등록 설정과 Kakao API | 인가·토큰 교환·ID Token 검증 | 기존 auth API 설계의 사용자 인증 절을 따른다 |

## 벗어난 것

상수 통합으로 새로 기본 처리를 벗어나는 대상은 없다. 기존 정책의 예외는 아직 전체를 훑지 않았다.

## 유형별 점검

### 캐시

| 시나리오 | 점검 결과 |
|---|---|
| 캐시 다운 | 이번 변경은 기존 예외·폴백 분기를 수정하지 않는다 |
| 캐시 스탬피드 | 이번 변경은 TTL이나 조회 횟수를 수정하지 않는다 |
| 분산 락 | 이번 변경은 Lua와 잠금 순서를 수정하지 않는다 |
| 낡은 값 | 기존 RT 키·마커를 유지해 저장소 사이의 호환성을 보존한다. 다른 시나리오는 아직 훑지 않았다 |

### DB

이번 변경은 DB 읽기·쓰기·잠금·트랜잭션을 수정하지 않는다. DB 장애 시나리오 전체는 아직 훑지 않았다.

### 외부 API

Kakao 등록 ID의 값과 설정 경로를 유지한다. 타임아웃·재시도·호출 차단과 외부 API 장애 시나리오 전체는 아직 훑지 않았다.

### 애플리케이션

상수 클래스는 불변 문자열만 제공한다. 처리 스레드와 배포 시나리오 전체는 아직 훑지 않았다.

### 롤백 안 되는 효과

상수 참조는 외부 효과를 만들지 않는다. 기존 DB와 Valkey의 부분 실패 처리는 auth API 설계를 따른다.

## 아직 정하지 못한 것

이번 상수 통합에 남은 미정 사항은 없다. 기존 인증 정책의 미정 사항은 auth API 설계의 해당 절을 따른다.
