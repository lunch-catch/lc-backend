# 포스터 (poster) API 설계

템플릿 관리 API를 서버가 어떻게 처리하는지와 그렇게 정한 이유를 적는다. 요청, 응답, 오류는 명세서 `poster-api-spec.md` 에 있고 여기서는 반복하지 않는다.

| 근거 | 기준 |
|---|---|
| 요구사항 | 명세서 V51 기능 14~17행(생성, 수정, 목록, 버전별 임시저장). 18~19행(게시, 활성화)은 아직 구현하지 않았다 |
| 저장 구조 | `db/migration/campaign/` 의 `V1`, `V4`~`V6`: `template`, `template_version`, `template_quota` |
| 설계 | `../architecture/런치캐치_도메인_구조와_의존성_설계.md` 1.2절(포스터·템플릿은 캠페인 애그리거트가 흡수) |

## 목록과 요구사항 행

| 메서드 | 경로 | 행 |
|---|---|---|
| `POST` | `/v1/admin/templates` | 14 |
| `POST` | `/v1/admin/templates/{templateId}/versions` | 15 |
| `GET` | `/v1/admin/templates` | 16 |
| `GET` | `/v1/admin/templates/{templateId}` | 16 (상세는 행에 별도 기술 없음, 목록과 같은 근거로 둠) |
| `GET` | `/v1/admin/templates/{templateId}/versions` | 17 |

## 템플릿 생성 · 수정

- LLM 호출은 트랜잭션 밖에서 한다(최대 30초 걸릴 수 있어 트랜잭션을 길게 잡지 않는다)
- `requestId` 로 재시도를 식별한다. 같은 `requestId` 가 이미 저장된 버전에 있으면 LLM 을 다시 부르지 않고 그 결과를 그대로 돌려준다
- 수정은 `findByIdForUpdate` 로 행 잠금을 잡고 버전 번호를 매긴다. 동시에 같은 템플릿을 수정하는 두 요청이 같은 번호를 매기는 경쟁을 막는다
- 정화(허용 태그/속성만 남김) → 슬롯 검증(필수 슬롯 존재) → 구조 검증(수정 시, 이전 버전과 슬롯 태그가 같은지) 순으로 검사한다

## 템플릿 목록 · 상세 조회

**서버가 하는 일**

1. 목록은 `createdAt` 내림차순 전체 조회다. 템플릿이 최대 10개로 제한돼 있어 페이지네이션을 두지 않았다(비기능 제약이 아니라 업무 규칙상 상한)
2. 목록과 상세 모두 `html` 미리보기를 포함한다. `status` 가 `PUBLISHED` 면 `template.html_content`(게시 시 복사된 값), `DRAFT` 면 최신 임시저장 버전의 `html_content` 다

**정한 이유**

- **목록에도 미리보기 html을 넣는다(16행 "게시된 템플릿은 확정 버전을, 임시저장중인 템플릿은 최신 임시저장 버전을 미리보기로 표시").** 상세와 같은 분기 로직(`htmlOf`)을 그대로 재사용한다. 템플릿이 최대 10개라 목록 전체에 미리보기를 포함해도 응답이 무겁지 않다
- **서버 검색·정렬·필터를 지원하지 않는다.** 템플릿이 최대 10개뿐이라 화면에서 처리하기로 최종 결정했다
- **`usageCount`(이 템플릿으로 만든 포스터 수)는 이번 범위에서 뺐다.** `poster` 도메인에 아직 코드가 없어 셀 데이터 소스가 없다. 항상 `0`을 내려주면 "진짜 0개"와 "집계 미구현"을 프론트가 구분할 수 없어, 포스터 도메인이 생기는 이슈에서 필드를 추가하기로 했다
- **`lastModifiedBy`/`lastModifiedAt` 은 `template` 테이블에 즉시 복사해 둔다.** 게시하는 순간 `template_version`이 소프트삭제되고 배치가 하드삭제하므로, `template_version` 쪽에만 수정자를 두면 게시된 템플릿은 조회 즉시 "수정자 없음"이 된다

## 템플릿 버전 목록 조회

- 소프트삭제(`deleted_at`)된 버전은 제외한다. 게시한 템플릿은 모든 버전이 삭제돼 있어 빈 배열이 된다
- 커서는 `versionNumber` 값 하나만 쓴다. 템플릿 안에서 유일하고 단조증가라 동점 처리용 키가 따로 필요 없다. 

## 오류 코드를 나눈 기준

요청 형식(필수값, 길이)처럼 판정에 업무 지식이 필요 없는 실패는 `COMMON-002` 를 쓴다.
`POSTER-` 코드는 템플릿의 상태와 구조를 봐야 판정할 수 있는 실패에만 둔다.

## 아직 정해지지 않은 것

| 항목 | 요구사항                                | 현재 스키마 또는 명세 |
|---|-------------------------------------|---|
| `usageCount`(포스터 생성 수) | 팀 미팅에서 "추가" 결정                      | `poster` 도메인 코드가 없어 집계할 데이터가 없다. 포스터 도메인이 생기는 이슈에서 추가한다 |
| 템플릿 게시(18행), 활성화 관리(19행) | 관리자가 임시저장 버전을 확정하고 활성화를 바꾸는 API     | 아직 구현하지 않았다. 로드맵상 "템플릿 게시와 활성화(관리자)" 이슈에서 다룬다 |
| 목록 상태/활성여부 필터(16행 원문) | 원문은 필터를 요구하지만 서버 필터를 지원하지 않기로 최종 결정 | 템플릿 최대 10개 제약 때문에 화면에서 처리. 개수 제한이 바뀌면 재검토 필요 |
