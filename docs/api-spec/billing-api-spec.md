# 정산 (billing) API 명세

정산 도메인의 HTTP API 명세서다. 공통 규약(경로, 인증, 응답 봉투, 상태 코드, 식별자, 시각)은 [api-spec.md](./api-spec.md)를 따르고 여기서 다시 적지 않는다.

이 문서는 지금 **관리자 포인트 수동 조정 하나만** 담는다. [api-spec.md의 문서 목록](./api-spec.md)이 이 문서의 범위로 적은 포인트 결제, 잔액과 내역, 환불, 관리자의 포인트 정책과 결제 내역은 아직 쓰지 않았다. 해당 기능을 맡은 작성자가 채운다. 코드에 구현이 있더라도 코드를 옮겨 적어 계약으로 삼지 않는다.

## 목록과 구현 범위

| 메서드 | 경로 | 기능 | 인증 및 권한 | 구현 |
| --- | --- | --- | --- | --- |
| `POST` | `/v1/admin/point-adjustments` | 포인트 수동 조정 | Access Token, `ADMIN` 또는 `SUPER_ADMIN` | 있음 |

## 포인트 수동 조정

관리자가 점주의 포인트 원장에 조정(`ADJUST`)을 한 줄 기록한다. 주 용도는 사후에 확인된 과오 차감을 양수로 돌려주는 정정이다. 같은 API로 잔액을 줄이는 음수 조정도 받는다.

```
POST /v1/admin/point-adjustments
```

### 요청

```json
{
  "requestId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "ownerId": 7,
  "amount": 1000,
  "reason": "중복 과금 정정",
  "campaignId": 12,
  "targetBusinessDate": "2026-10-13",
  "mismatchId": 55
}
```

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `requestId` | string | 필수 | 멱등 키. 1자 이상 64자 이하. 관리자 화면이 조정 폼을 열 때 한 번 만들고 같은 폼의 재전송에는 같은 값을 쓴다 |
| `ownerId` | number | 필수 | 조정 대상 점주. 탈퇴, 정지한 점주도 받는다 |
| `amount` | number | 필수 | 부호를 가진 포인트. 0이 아니어야 한다. 양수는 과오 차감을 돌려주는 정정이고 음수는 잔액을 줄인다. 1포인트가 1원이다 |
| `reason` | string | 필수 | 조정 사유. 1자 이상 255자 이하 |
| `campaignId` | number | 선택 | 정정이 가리키는 캠페인. 캠페인에 묶이지 않는 조정이면 보내지 않는다 |
| `targetBusinessDate` | string(`YYYY-MM-DD`) | 조건부 | 정정이 가리키는 원래 영업일. `campaignId`를 보내면 필수이고 보내지 않으면 보낼 수 없다. 오늘(KST) 이후는 보낼 수 없다 |
| `mismatchId` | number | 선택 | 닫으려는 대사 불일치 건. 보내면 이 조정이 그 건을 과과금 정정으로 닫는다 |

- **`targetBusinessDate`는 어느 날의 과금을 고치는지 정한다.** 분석의 소진액(`DEDUCT` 합 − 양수 `ADJUST` 합)에서 이 정정은 `targetBusinessDate`의 영업일에 붙는다. 기록한 날에 붙지 않는다. 캠페인 없는 조정은 영업일이 없어 기록한 날에 붙는다.
- **대사 불일치 건을 닫는 조정은 양수만 받는다.** 과오 차감 정정이기 때문이다.
- **캠페인 대사 건(`CAMPAIGN_SPEND_VS_LEDGER`, `CAMPAIGN_OVERSPEND`)을 닫을 때는** `campaignId`가 그 건의 대상 캠페인과 같아야 하고 `targetBusinessDate`가 그 건의 영업일과 같아야 한다. 결제 대사 건(`PG_VS_CHARGE`)은 캠페인과 무관하다.
- **같은 점주가 같은 `requestId`로 다시 보내면** 내용이 같을 때 처음 결과를 `200`으로 돌려주고 새로 기록하지 않는다. 비교하는 필드는 `amount`, `campaignId`, `targetBusinessDate`, `reason`이다. 하나라도 다르면 `409`다. `mismatchId`는 비교하지 않는다.
- **음수 조정은 조정 뒤 잔액이 음수가 되면 거절한다.**

### 응답 `201`

새로 기록했다. 같은 요청을 이미 처리했으면 같은 본문을 `200`으로 돌려준다.

```json
{
  "code": "SUCCESS",
  "message": "요청이 성공적으로 처리되었습니다.",
  "data": {
    "ledgerId": 9101,
    "ownerId": 7,
    "amount": 1000,
    "campaignId": 12,
    "targetBusinessDate": "2026-10-13",
    "reason": "중복 과금 정정",
    "createdAt": "2026-10-14T11:20:00+09:00"
  }
}
```

| 필드 | 타입 | null | 설명 |
| --- | --- | --- | --- |
| `ledgerId` | number | 아니오 | 기록된 원장 줄의 ID |
| `ownerId` | number | 아니오 | 조정 대상 점주 |
| `amount` | number | 아니오 | 기록된 부호 있는 포인트 |
| `campaignId` | number | 가능 | 캠페인 없는 조정이면 `null` |
| `targetBusinessDate` | string(`YYYY-MM-DD`) | 가능 | 캠페인 없는 조정이면 `null` |
| `reason` | string | 아니오 | 조정 사유 |
| `createdAt` | string | 아니오 | 기록 시각. 오프셋을 포함한 ISO 8601 |

### 오류 코드

| 코드 | 상태 | 메시지 | 언제 |
| --- | --- | --- | --- |
| `COMMON-002` | `400` | 입력값이 올바르지 않습니다. 요청 형식을 확인해 주세요. | 필수값이 없다. 금액이 0이다. 대사 건을 닫는데 금액이 음수다. `campaignId`와 `targetBusinessDate`의 짝이 맞지 않는다. `targetBusinessDate`가 오늘 이후다. 캠페인 대사 건인데 `campaignId`가 대상 캠페인과 다르거나 `targetBusinessDate`가 그 건의 영업일과 다르다 |
| `BILLING-019` | `404` | 점주를 찾을 수 없습니다. | `ownerId`의 점주가 없다 |
| `BILLING-020` | `404` | 대사 불일치 건을 찾을 수 없습니다. | `mismatchId`의 건이 없다 |
| `BILLING-016` | `409` | 조정 후 잔액이 음수가 되어 처리할 수 없습니다. | 음수 조정 뒤 잔액이 0보다 작아진다 |
| `BILLING-018` | `409` | 같은 키로 내용이 다른 요청이 이미 처리되었습니다. | 같은 `requestId`로 `amount`, `campaignId`, `targetBusinessDate`, `reason` 중 하나가 다르다 |
| `BILLING-021` | `409` | 이미 해결된 대사 불일치 건입니다. | 닫으려는 건이 이미 해결됐다 |
| `BILLING-022` | `409` | 대사 불일치 건이 조정 대상 점주의 것이 아닙니다. | 건의 대상 결제나 캠페인의 점주가 `ownerId`와 다르다 |
| `BILLING-006` | `503` | 잔액을 조회할 수 없습니다. 잠시 후 다시 시도해 주세요. | 점주의 포인트 계정 행을 잠그지 못했다. 같은 `requestId`로 다시 보낸다 |

권한이 없으면 `403`, 로그인하지 않았거나 토큰이 만료됐으면 `401`이다. 코드는 [공통 규약](./api-spec.md)과 [인증 명세](./auth-api-spec.md#오류-코드)를 따른다.

### 클라이언트 규칙

- **`requestId`는 폼을 열 때 만든다.** 응답을 받지 못해 재전송할 때 같은 값을 써야 중복 기록이 생기지 않는다. `503`을 받았을 때도 같은 값으로 다시 보낸다.
- **캠페인을 고르면 정정 대상 영업일 입력을 보여 준다.** 오늘 이후 날짜는 고르지 못하게 막는다.
- **대사 불일치 건을 닫는 화면은 건의 영업일을 `targetBusinessDate`에 미리 채운다.** 대사 불일치 목록 응답의 `businessDate`를 쓴다. 관리자가 바꿔도 서버는 건의 영업일과 다르면 `400`으로 거절한다.
- **`409 BILLING-018`을 받으면 같은 `requestId`로 다른 내용을 보낸 것이다.** 폼을 다시 열어 새 `requestId`를 만들고 보낸다.

## 아직 정해지지 않은 것

| 항목 | 현재 | 정할 사람 |
| --- | --- | --- |
| 이 문서에 없는 정산 API | 포인트 결제, 잔액과 내역, 환불, 관리자의 포인트 정책과 결제 내역, 대사 불일치 조회, 원장 조회는 아직 쓰지 않았다 | 정산 담당 |
| `targetBusinessDate`의 과거 하한 | 하한이 없다. 오늘 이전이면 몇 년 전도 받는다 | 명세 작성자 |
| 정정 대상 영업일의 예산 계획 존재 확인 | 하지 않는다. 그 영업일에 그 캠페인의 계획이 없어도 받는다 | 명세 작성자 |
