# 분류별 장면

다섯 분류는 발표 자료에서 자주 쓰는 그림 다섯 가지다. 분류마다 예시 spec 이 `examples/` 에 있다.
새 장면은 예시를 복사해 상자 수와 글자를 바꾸는 것으로 시작한다.

모든 분류에 공통인 것은 아래와 같다.

- 제목은 결론 한 문장이다. `~합니다.` 로 끝내고 한 줄을 넘기지 않는다. 한글 기준 28자 안이다.
- 강조색은 장면에서 가장 중요한 것 하나에만 쓴다. 나머지는 회색 단계로 위계를 만든다.
- 한 반복은 15 ~ 25초다. 움직임이 끝난 뒤 1.5 ~ 2.5초 멈춰서 결과를 읽을 시간을 둔다.
- 배경 움직임(`every` 트랙)은 하나나 둘만 둔다. 많으면 주인공 움직임이 묻힌다.

## 설계

예시는 `examples/설계.json` 이고 adserving 도메인의 내부를 펼친다.

| 자리 | 놓는 것 |
|---|---|
| 왼쪽 열 (x 70, 폭 290) | 요청이 지나는 계층을 위에서 아래로 쌓는다. 펼칠 층 하나에 `tone: accent` 를 준다 |
| 오른쪽 큰 panel (x 420 ~ 1530) | 펼친 층의 이름과 한 줄 설명. 왼쪽의 강조 층에서 이 panel 의 두 모서리로 점선을 긋는다 |
| panel 위쪽 띠 | 요청이 들어와 나가는 주 흐름 상자 셋 |
| panel 아래 세 열 | 하위 모듈. 열마다 상자 2 ~ 3개와 바닥의 `cells` 하나 |

움직임은 주 흐름을 점이 지나간 뒤, 그 결과를 받는 열로 내려가 칩이 차례로 켜지고 칸이 차는 순서다.
열 셋이 동시에 움직이면 읽기 어렵다. `par` 로 겹치더라도 시작을 0.5 ~ 1초씩 어긋나게 둔다.

## 워커

예시는 `examples/워커.json` 이고 피드 10장의 배분과 관련성 슬롯 배정을 보인다.

| 자리 | 놓는 것 |
|---|---|
| 위 panel 왼쪽 | 요청을 내는 상자 하나 |
| 위 panel 가운데 | 판정하는 상자. 안에 `rows` 로 후보나 워커의 표를 둔다. 줄마다 `bar` 와 `meta` 가 있다 |
| 위 panel 오른쪽 | 갈래 상자 2 ~ 4개. 상자마다 `cells` 대기열을 둔다. 버려지는 갈래는 `tone: ghost` 와 점선이다 |
| 아래 panel 두 개 | 판정에 쓰는 수식. 제목 한 문장, `formula`, 기호 풀이 `label` |

움직임은 요청 점이 판정 상자로 들어가고, 표의 한 줄이 켜져 `meta` 가 판정으로 바뀐 뒤, 그 색의 점이 갈래로 가서 칸 하나를 채우는 순서다.
갈래 색은 `a`, `b`, `warn` 처럼 갈래마다 하나로 고정한다. 수식의 숫자는 코드의 상수와 같아야 한다.

## 오토스케일링

예시는 `examples/오토스케일링.json` 이고 lc-infra 의 API 서버 ASG 를 보인다.

| 자리 | 놓는 것 |
|---|---|
| 맨 위 한 줄 | 제어 루프 상자 셋. 지표 -> 계산 -> 실행이다. 지표 상자에 `progress` 와 `value` 를 둔다 |
| 가운데 점선 panel | 앞단(ALB 같은 것), 서버 열, 데이터 열. 아직 없는 서버는 `tone: ghost` 와 점선 연결로 둔다 |
| 맨 아래 한 줄 | 새 서버가 일을 받기까지의 단계와 걸리는 시간. 상자마다 `progress` 가 있다 |

움직임은 배경 요청이 계속 흐르는 동안 지표가 차오르고, 넘치면 강조색 점이 계산과 실행을 거쳐 ghost 서버로 간다.
그 서버가 켜지면 아래 단계의 진행 바가 차례로 차고, 다 차면 그 서버에도 요청 점이 흐른다. 마지막에 지표가 목표 아래로 내려온다.
지표, 목표, 대수, 소요 시간은 Terraform 값과 주석의 실측값을 그대로 쓴다.

## 워크플로우

예시는 `examples/워크플로우.json` 이고 00:00 배치 묶음 10단계를 보인다.

| 자리 | 놓는 것 |
|---|---|
| 위 panel | 단계 전체를 감싸는 운영 규칙. 오른쪽에 작은 상자 3 ~ 4개를 화살표로 잇고, 되돌아가는 점선을 둔다 |
| 가운데 카드 줄 | 단계 카드. 한 줄에 5 ~ 6장이고 많으면 두 줄로 나눈다. 카드는 `icon`, `num`, `title`, `sub`, `progress` 를 가진다 |
| 맨 아래 | 실패하거나 되돌아갈 때의 규칙 한 문장 |

움직임은 카드가 하나씩 `active` 로 켜지며 진행 바가 차고, 점이 다음 카드로 넘어가는 순서다.
`num` 에는 순서를 정하는 실제 값(`@Order(10)` 같은 것)을 쓴다. 순서를 지어내지 않는다.

## 동작

예시는 `examples/동작.json` 이고 쿠폰 발급을 요청마다 트랜잭션 하나에서 묶음마다 트랜잭션 하나로 바꾼 것을 보인다.

| 자리 | 놓는 것 |
|---|---|
| 왼쪽 panel (x 70, 폭 470) | 위에 Before, 아래에 After. Before 는 점선 panel 안에서 같은 일을 되풀이하는 고리와 횟수 `label` 이다. After 는 모으는 상자와 한 번에 처리하는 상자, 그 안의 `cells` 다 |
| 오른쪽 panel 왼쪽 | 대기열 상자. 안에 `rows` 로 요청을 줄 세운다 |
| 오른쪽 panel 가운데 | 작업자를 세로로 쌓은 점선 panel. 작업자 상자마다 하위 단계 `chips` 와 `progress` 를 둔다 |
| 오른쪽 panel 오른쪽 | 작업자가 결과를 쓰는 저장소. 맨 아래 점선은 결과가 요청에게 돌아가는 길이다 |

움직임은 왼쪽과 오른쪽이 따로 돈다. 왼쪽 Before 는 점이 고리를 돌 때마다 횟수가 오르고, After 는 칸이 차면 한 번에 강조색으로 바뀐다.
오른쪽은 요청이 들어와 줄이 켜지고, 작업자가 그 줄을 가져가 칩을 차례로 켜며 진행 바를 채운 뒤 저장소로 점을 보낸다.
작업자마다 시작을 0.8초쯤 어긋나게 두면 여럿이 동시에 일하는 것이 보인다. 이때 줄은 `row` 단계의 `on` 으로 켜고 꺼서 다른 줄의 강조를 지우지 않는다.
작업자 수, 묶음 상한, 대기열 크기 같은 숫자는 설정 파일의 값을 그대로 쓴다.
