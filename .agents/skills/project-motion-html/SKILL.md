# 이해를 돕는 HTML 애니메이션

사용자가 설명하고 싶은 것을 받아 근거 자료에서 사실을 읽고, 그 내용에 맞는 장면을 처음부터 짜서 HTML 파일 하나로 만든다.
결과 HTML 은 브라우저로 열면 무대가 창 크기에 맞춰 늘고 줄며 끝없이 되풀이된다. 무대를 누르면 멈추고 다시 누르면 이어 간다. GIF 가 필요하면 `project-motion-gif` 스킬을 쓴다.
장면은 분류를 고르지 않는다. [화면 문법](reference/visual-language.md)과 [패턴 모음](reference/patterns.md)에서 필요한 것을 골라 섞는다.

아래에서 `$S` 는 이 SKILL.md 가 있는 폴더다. 작업 파일은 모두 작업 폴더의 `project-motion/{이름}/` 에 둔다.

## 1. 요청을 장면의 질문으로 바꾼다

요청에서 아래 셋을 정한다. 하나라도 정할 수 없으면 사용자에게 묻고 멈춘다.

- **질문**: 이 장이 답하는 질문 하나. "주문 저장이 왜 느렸나", "11시에 서버가 어떻게 늘어나나"
- **결론**: 그 질문의 답 한 문장. 이것이 제목이 된다. 명사로 끝내고 마침표를 찍지 않는다. `묶음으로 발급합니다.` 가 아니라 `묶음으로 발급` 이다. 한글 30자 안팎으로 쓴다
- **변화**: 보는 사람이 그림에서 확인할 변화 하나. 무엇이 무엇으로 바뀌는지, 무엇이 무엇보다 큰지

보여줄 것이 여럿이면 둘의 관계를 본다. 원인과 결과로 이어지면 한 장에 두고 앞의 것을 무대로, 뒤의 것을 변화로 삼는다. "설계와 동작" 처럼 따로 설명할 수 있으면 장을 나누자고 먼저 제안한다.

## 2. 근거를 모은다

장면의 이름, 숫자, 순서, 코드 줄은 근거에서 가져온다. 추측한 값을 넣지 않는다. 어디서 읽고 숫자를 어떻게 옮기는지는 [reference/sources.md](reference/sources.md) 가 갖는다.
근거가 될 코드나 문서가 대화에 없으면 무엇이 필요한지 묻는다. 저장소 주소, 첨부 파일, 연결된 앱의 문서 가운데 하나면 된다.

## 3. 장면을 설계하고 확인받는다

[화면 문법](reference/visual-language.md)을 읽고 [패턴 모음](reference/patterns.md)의 "어떤 질문에 어떤 패턴을 쓰나" 표에서 시작한다.
패턴은 섞어 써도 된다. 어느 패턴에도 맞지 않으면 화면 문법만 지켜 새로 짠다.

아래를 짧게 정리해 사용자에게 보이고 답을 받은 뒤 진행한다.

- 제목(결론 문장)
- 화면 나눔과 각 영역에 놓을 것, 쓰는 패턴 번호
- 움직임의 순서와 대략의 박자
- 화면에 쓸 기술 용어. [화면 문법](reference/visual-language.md) 6장의 용어 규칙을 따른다
- 근거 파일 목록

## 4. 장면 정의를 쓴다

`project-motion/{이름}/{이름}.json` 을 [reference/scene.md](reference/scene.md) 형식으로 쓴다. 이름은 주제를 두세 단어로 줄여 `-` 로 이은 것이다. 한글, 영문, 숫자, `-` 만 쓰고 20자 안으로 둔다.

- 좌표는 화면 문법 2장의 영역 안에 둔다. 패널 안 요소는 `parent` 로 두고 패널 기준 좌표로 적는다.
- `logo` 에는 그 프로젝트 이름을 대문자로 적는다. 모르면 비운다.
- `sources` 에 근거 파일을 적는다.
- 코드로 정할 수 없는 값(요청 수, 가게 이름 같은 것)은 예시 값으로 넣고 장면 안에 예시라고 적는다.

## 5. 엔진을 준비한다

처음 한 번만 한다. Node 18 이상이 있어야 한다. 스킬 폴더는 읽기 전용일 수 있으니 엔진을 작업 폴더로 복사해 쓴다.

```bash
mkdir -p out && cp -r $S/engine ./engine
cd engine && npm install && npx playwright install chromium; cd ..
E=$PWD/engine
```

크로미움은 6단계의 정지 화면 확인에만 쓴다. 내려받기가 막히면 이미 깔린 Playwright 와 크로미움이 있는지 본다(`node -e "require('playwright')"`). 있으면 그것을 쓴다.
둘 다 없으면 6단계를 건너뛰고 `build.js` 의 경고만 없앤 뒤 7단계로 간다. 이때는 배치를 눈으로 확인하지 못했다고 결과와 함께 알린다.

## 6. 정지 화면으로 확인한다

```bash
node $E/build.js project-motion/{이름}/{이름}.json project-motion/{이름}/{이름}.html
node $E/record.js project-motion/{이름}/{이름}.html project-motion/{이름}/{이름}-a.png --still 800
node $E/record.js project-motion/{이름}/{이름}.html project-motion/{이름}/{이름}-b.png --still {주인공 움직임이 한창인 시각}
node $E/record.js project-motion/{이름}/{이름}.html project-motion/{이름}/{이름}-c.png --still {loop 에서 1500 을 뺀 값}
```

`build.js` 와 `record.js` 가 내는 경고를 모두 없앤다. 그다음 PNG 세 장을 직접 열어 보고 아래 중 하나라도 보이면 고치고 다시 찍는다.

- 글자가 잘리거나 상자를 넘친다
- 클래스 이름 같은 영문 제목이 단어 중간에서 꺾인다. 상자를 넓힌다
- 선이 상자나 글자 위를 지난다
- 큰 빈 곳이 한쪽에 몰려 있다. 패널 크기를 내용에 맞춘다
- 같은 뜻에 다른 색을 쓰거나 다른 뜻에 같은 색을 쓴다
- 마지막 장면에서 결론이 그림으로 보이지 않는다
- 한 반복이 끝나기 전에 움직임이 잘린다. 잘리면 `loop` 를 늘린다

## 7. HTML 을 만들어 건넨다

```bash
node $E/pack.js project-motion/{이름}/{이름}.html project-motion/{이름}/{이름}-final.html            # 글꼴을 구글 폰트에서 불러온다. 약 0.1MB
node $E/pack.js project-motion/{이름}/{이름}.html project-motion/{이름}/{이름}-final.html --offline  # 글꼴을 파일에 넣는다. 약 1.5MB
```

사용자가 어디에 둘지 말했으면 그에 맞춰 고른다. 말이 없으면 `--offline` 을 쓴다. 어디서 열어도 글꼴이 같게 보인다.

| 쓰는 곳 | 고르는 것 |
|---|---|
| 내려받아 브라우저로 연다, 인터넷이 없는 곳에서 연다 | `--offline` |
| GitHub Pages, 사내 위키, 블로그에 올린다 | 기본 |
| Canva, Notion 같은 곳에 웹 주소로 임베드한다 | 기본으로 만들어 올린 뒤 그 주소를 쓴다 |

`project-motion/{이름}/{이름}-final.html` 을 `{이름}.html` 로 이름을 바꿔 사용자에게 파일로 보내고 한 반복의 길이, 크기, 근거 파일 목록을 알린다. 장면 `.json` 은 다시 고칠 때 쓰니 함께 보내도 된다. 확인용 PNG 는 지운다.

## 규칙

- 결과물은 HTML 파일 하나다. 외부 파일 없이 혼자 열린다.
- 엔진과 참고 문서를 고치는 것은 이 작업의 일이 아니다. 엔진이 표현하지 못하는 장면이면 무엇이 모자란지 알리고 멈춘다.
- 근거로 받은 저장소에 커밋, 푸시, 이슈, PR 을 만들지 않는다. 읽기만 한다.
- 장면의 어느 글에도 `~니다` 를 쓰지 않는다. 제목은 명사로, 나머지는 `~다` 로 끝낸다.
- 장면의 문장은 동사로 끝내고 em dash 와 가운뎃점을 쓰지 않는다. 화살표는 `->` 로 쓴다. 프로젝트에 문장 규칙 문서가 있으면 그것도 따른다.
- 속도가 빠르다는 말을 들으면 `speed` 를 낮추고 `loop` 를 늘린다. 같은 장면을 고칠 때는 같은 이름으로 덮어쓴다.
- 사용자가 새 참고 영상을 주며 배우라고 하면 [reference/learn.md](reference/learn.md) 를 따른다.
