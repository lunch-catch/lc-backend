# 어디를 읽는가

장면의 사실은 코드가 기준이다. 문서는 코드를 찾아가는 길로 쓰고 둘이 다르면 코드를 따른다.

## 근거를 손에 넣는다

| 근거가 있는 곳 | 하는 일 |
|---|---|
| 공개 저장소 주소 | `git clone --depth 50 <주소> src/<이름>` 으로 받는다. 사용자가 브랜치를 말하면 그 브랜치를, 말이 없으면 기본 브랜치를 쓴다 |
| 비공개 저장소 | 이 환경에서 읽을 수 있는지 먼저 본다. 읽을 수 없으면 필요한 파일을 첨부해 달라고 한다 |
| 첨부 파일, 붙여 넣은 코드 | 그대로 읽는다 |
| 연결된 앱의 문서 | 그 앱의 도구로 읽는다 |
| 근거 없이 개념만 설명 | 일반적으로 알려진 사실만 쓰고 수치는 예시라고 적는다 |

최근 커밋이 그리려는 주제를 바꿨는지 `git log --oneline -15` 로 본다. 바뀌었으면 `git show <커밋>` 으로 무엇이 바뀌었는지 읽는다.
장면 아래 출처 줄에는 읽은 브랜치와 커밋을 적는다.

## 주제별 시작점

| 주제 | 먼저 읽는 곳 |
|---|---|
| 모듈 경계와 계층 | 아키텍처 문서, 최상위 패키지 구조 |
| 한 기능의 동작 | 진입점(컨트롤러, 핸들러) -> 서비스 -> 저장소 순서로 호출을 따라간다 |
| 규칙과 순서 | 규칙 목록을 가진 클래스, 상수, 정렬 기준 |
| 비동기, 큐, 배치 | 스케줄러, 큐와 작업자 설정, 설정 파일의 기본값 |
| 장애 대응 | 장애 처리 설계 문서, 재시도와 우회 코드, 지표 이름 |
| 부하 시험 결과 | 결과 문서의 표 |
| 인프라 | Terraform, Kubernetes, 배포 설정 |

표에 없는 주제는 `grep -rn` 으로 클래스 이름과 설계서를 찾는다. 같은 주제의 설계서가 버전별로 여럿이면(`-v1`, `-v2`) 번호가 가장 큰 것이 지금의 설계다. 그래도 코드와 대조한다.
"몇 건", "얼마나 빨라졌나" 처럼 양을 묻는 요청은 코드만으로 답할 수 없다. 부하 시험 결과나 운영 지표 문서를 찾고, 없으면 예시 값임을 밝히거나 사용자에게 묻는다.

## 숫자를 옮길 때

- 상수는 정의된 자리를 찾아 그 값을 쓴다. 주석에 적힌 값과 코드의 값이 다르면 코드를 쓴다.
- 설정값은 설정 파일과 인프라 변수의 기본값을 쓴다. 환경 변수로 덮을 수 있다는 것은 장면에 적지 않는다.
- 부하 시험의 수치는 결과 문서의 표를 그대로 쓰고, 측정 회차와 날짜를 장면 아래 한 줄로 적는다.
- 예시 값(번호, 이름, 곡선의 모양 같은 것)을 쓰면 장면 안에 예시라고 적는다.
- 코드를 장면에 옮길 때는 실제 줄을 쓴다. 줄이 길면 인자를 `...` 로 줄이되 뜻을 바꾸지 않는다.
