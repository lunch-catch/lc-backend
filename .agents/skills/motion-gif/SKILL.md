# 요청에 맞춘 발표용 GIF

사용자가 설명하고 싶은 것을 받아 코드에서 사실을 읽고, 그 내용에 맞는 장면을 처음부터 짜서 GIF 로 만든다.
장면은 분류를 고르지 않는다. [화면 문법](reference/visual-language.md)과 [패턴 모음](reference/patterns.md)에서 필요한 것을 골라 섞는다.
결과물은 GIF 하나다. 요청은 사용자가 이 스킬을 부르며 적은 문장이다.

## 1. 요청을 장면의 질문으로 바꾼다

요청에서 아래 셋을 정한다. 셋 중 하나라도 정할 수 없으면 사용자에게 묻고 멈춘다.

- **질문**: 이 장이 답하는 질문 하나. "노출 저장이 왜 느렸나", "11시에 서버가 어떻게 늘어나나"
- **결론**: 그 질문의 답 한 문장. 이것이 제목이 된다. `~합니다.` 로 끝낸다
- **변화**: 보는 사람이 그림에서 확인할 변화 하나. 무엇이 무엇으로 바뀌는지, 무엇이 무엇보다 큰지

요청에 보여줄 것이 여럿이면 둘의 관계를 본다. 하나가 다른 하나의 원인이나 결과라 한 이야기로 이어지면 한 장에 두고, 앞의 것을 무대로 뒤의 것을 변화로 삼는다. 서로 따로 설명할 수 있으면 장을 나누자고 사용자에게 먼저 제안한다.

## 2. 코드를 읽고 사실을 모은다

장면의 이름, 숫자, 순서, 코드 줄은 모두 코드와 문서에서 가져온다. 추측한 값을 넣지 않는다.
어디를 읽을지와 숫자를 옮기는 규칙은 [reference/sources.md](reference/sources.md) 가 갖는다. 먼저 develop 을 최신으로 맞춘다.

## 3. 장면을 설계하고 확인받는다

[화면 문법](reference/visual-language.md)을 읽고 [패턴 모음](reference/patterns.md)의 "어떤 질문에 어떤 패턴을 쓰나" 표에서 시작한다.
패턴은 하나만 고르지 않아도 된다. 왼쪽은 패턴 7, 오른쪽은 패턴 8 처럼 섞는다. 어느 패턴에도 맞지 않으면 화면 문법만 지켜 새로 짠다.

아래를 짧게 정리해 사용자에게 보이고 답을 받은 뒤 진행한다.

- 제목(결론 문장)
- 화면 나눔과 각 영역에 놓을 것. 쓰는 패턴 번호가 있으면 함께 적는다
- 움직임의 순서와 대략의 박자
- 근거 파일 목록

## 4. 장면 정의를 쓴다

결과물은 저장소 루트의 `.slides/` 에 둔다. 파일 이름은 주제를 두세 단어로 줄여 `-` 로 이은 것이다. 한글, 영문, 숫자, `-` 만 쓰고 20자 안으로 둔다. `00:00 배치 묶음을 두 서버 중 한 대만...` 이면 `배치-이어받기` 다. 아래 명령의 `{이름}` 이 그 값이다.
`.slides/{이름}.json` 을 [reference/scene.md](reference/scene.md) 형식으로 쓴다.
[gallery/](gallery/) 의 장면은 요소와 단계를 어떻게 쓰는지 보는 예다. 복사해서 고쳐도 되고 처음부터 써도 된다.

좌표는 화면 문법 2장의 영역 안에 둔다. 패널 안 요소는 `parent` 로 두고 패널 기준 좌표로 적는다.
`sources` 에 근거 파일을 적는다.

## 5. 엔진을 준비한다

처음 한 번만 한다. Node 18 이상이 있어야 한다.

```bash
cd .agents/skills/motion-gif/engine
npm install
npx playwright install chromium
```

## 6. 정지 화면으로 확인한다

저장소 루트에서 돌린다.

```bash
E=.agents/skills/motion-gif/engine
node $E/build.js .slides/{이름}.json .slides/{이름}.html
node $E/record.js .slides/{이름}.html .slides/{이름}-a.png --still 800
node $E/record.js .slides/{이름}.html .slides/{이름}-b.png --still {주인공 움직임이 한창인 시각}
node $E/record.js .slides/{이름}.html .slides/{이름}-c.png --still {loop 에서 1500 을 뺀 값}
```

`build.js` 와 `record.js` 가 내는 경고를 모두 없앤다. 그다음 PNG 세 장을 직접 열어 본다. 아래 중 하나라도 보이면 고치고 다시 찍는다.

- 글자가 잘리거나 상자를 넘친다
- 선이 상자나 글자 위를 지난다
- 큰 빈 곳이 한쪽에 몰려 있다. 패널 크기를 내용에 맞춘다
- 같은 뜻에 다른 색을 쓰거나 다른 뜻에 같은 색을 쓴다
- 마지막 장면에서 결론이 그림으로 보이지 않는다

## 7. GIF 를 만든다

```bash
node $E/record.js .slides/{이름}.html .slides/{이름}.gif
```

결과물은 GIF 하나다. 한 반복(`loop`)을 그대로 찍으므로 끝과 처음이 이어진다.
`.slides/` 에 남는 `.json` 과 `.html` 은 다시 고칠 때 쓰는 작업 파일이라 지우지 않는다. 확인용 PNG 는 GIF 를 만든 뒤 지운다.
끝나면 GIF 의 경로와 크기, 근거 파일 목록을 알린다.

## 규칙

- 결과물은 `.slides/` 에만 둔다. git 이 무시하는 경로다.
- 엔진, 갤러리, 참고 문서를 바꾸는 것은 이 작업의 일이 아니다. 엔진이 표현하지 못하는 장면이면 무엇이 모자란지 알리고 멈춘다.
- 사용자가 새 참고 영상을 주며 배우라고 하면 [reference/learn.md](reference/learn.md) 를 따른다.
- 장면의 문장도 저장소의 문장 규칙(`AGENTS.md`)을 따른다. em dash 와 가운뎃점을 쓰지 않고 화살표는 `->` 로 쓴다.
- 속도가 빠르다는 말을 들으면 `speed` 를 낮추고 `loop` 를 늘린다. 같은 장면을 고칠 때는 같은 `{이름}` 으로 덮어쓴다.
