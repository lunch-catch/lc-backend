# 화면 문법

참고 영상(토스 SlashLive "토스는 AI 모델을 어떻게 서빙할까", 21분, 슬라이드 45장)을 장면마다 프레임으로 뜯어 보고 정리한 규칙이다.
영상의 내용이나 로고를 옮기지 않는다. 옮기는 것은 화면을 나누는 방식, 색을 쓰는 방식, 움직이는 방식이다.

## 1. 한 장은 질문 하나에 답한다

영상의 슬라이드는 모두 제목이 결론 문장이다. "병목은 GPU 연산이 아닌 프레임워크 오버헤드." 처럼 읽기만 해도 답이 나온다.
그림은 그 문장의 근거다. 그래서 장면을 짜기 전에 아래 두 가지를 먼저 정한다.

- 이 장이 답하는 질문 하나
- 보는 사람이 그림에서 확인할 변화 하나. 무엇이 무엇으로 바뀌는지, 무엇이 무엇보다 큰지

변화가 둘 이상이면 장을 나눈다. 영상도 같은 주제를 "문제 -> 원인 -> 해결 -> 결과" 네 장으로 나눴다.

## 2. 무대와 영역

| 자리 | 값 |
|---|---|
| 무대 | 1600 x 900 |
| 제목 | x 100, y 78, 46px 굵게. 한 줄은 한글 34자 안이다. 넘으면 `\n` 으로 두 줄로 쓰고, 두 줄은 y 56 에서 시작한다 |
| 내용 영역 | x 100 ~ 1500, y 180 ~ 840. 두 줄 제목이면 y 200 부터 |
| 큰 패널 | 내용 영역 안에 1 ~ 3개. 패널 사이 간격 24 ~ 30 |
| 패널 안 여백 | 왼쪽과 위 22 ~ 26. 패널 제목이 있으면 내용은 y 96 ~ 120 부터 |
| 출처 한 줄 | 내용 영역 아래 y 830 ~ 850 의 작은 회색 글자 |

영상에서 자주 나온 나눔은 아래 넷이다. 정해진 틀이 아니라 출발점이다.

| 나눔 | 쓰는 때 | 영상 |
|---|---|---|
| 한 판 | 지도나 흐름 하나를 크게 보일 때 | 2:53 계층 지도, 16:29 게이트웨이 분기 |
| 좌우 반반 | 둘을 견주거나 문제 둘을 나란히 보일 때 | 2:05 두 문제, 7:29 A/B 구조 |
| 좌 1/3 + 우 2/3 | 왼쪽에 결론 숫자나 원인, 오른쪽에 동작 | 3:53 대규모, 5:01 고리 비율 + 순차 처리 |
| 위 띠 + 아래 칸 | 위에 요약 수치 줄, 아래에 상세 그림 | 4:05 목표 대비, 6:45 결과 세 칸 |

## 3. 면의 위계

면은 세 단계뿐이다. 바깥에서 안으로 갈수록 조금씩 밝아진다.

| 단계 | 요소 | 모양 |
|---|---|---|
| 무대 | 배경 | 거의 검정. 아래 왼쪽에 아주 옅은 빛 |
| 패널 | `panel` | 무대보다 살짝 밝은 면, 둥근 모서리 16, 아주 옅은 테두리 |
| 상자 | `box`, `stat` 을 담은 `panel`, `code` | 패널보다 한 단계 밝은 면, 모서리 12 |
| 조각 | `chip`, `cell`, `row` | 작은 칩과 칸 |

그림자는 쓰지 않는다. 켜진 상태는 테두리를 밝게 하고 면을 한 단계 밝게 하는 것으로만 보인다.

## 4. 색

기본은 회색 단계다. 의미가 있는 색은 둘이다.

| 색 | 토큰 | 뜻 | 영상 |
|---|---|---|---|
| 청록 | `good` | 우리가 고친 쪽, 기준을 통과한 값, 수락 | 6:45 결과 막대, 13:21 수락 토큰 |
| 장미 | `bad` | 문제, 기준을 넘은 값, 오버헤드, 거절 | 4:05 초과 막대, 5:01 95.4% 고리, SLA 점선 |
| 주황 | `accent` | 런치캐치의 강조. 장면에서 가장 중요한 것 하나 | 영상에는 없다. 우리 브랜드 색이다 |

색은 한 장에서 같은 뜻으로만 쓴다. 청록을 "통과" 로 썼으면 다른 뜻으로 청록을 쓰지 않는다.
갈래가 셋 이상이라 색이 더 필요하면 `a`(민트), `b`(보라), `warn`(노랑)을 점과 칸에만 쓴다.

## 5. 글자

| 자리 | 크기 | 요소 |
|---|---|---|
| 제목 | 46 굵게 | spec 의 `title` |
| 패널 제목 | 20 반굵게 | `panel.title` |
| 패널 위 작은 머리말 | 11 고정폭 회색 | `panel.eyebrow`. "01  문제" 나 파일 이름 |
| 상자 제목 | 14 ~ 22 | `box.title` |
| 설명 | 12 ~ 13 회색 | `sub`, `label` |
| 큰 숫자 | 32 ~ 76 굵게, 단위는 작게 | `stat` |
| 아주 큰 단어 | 88 굵게 | `label` 의 `size: xxl`. "대규모", "SLA", "???" 같은 한 단어 |

글은 짧게 쓴다. 상자 설명은 한 줄, 길어도 두 줄이다. 문장은 동사로 끝낸다.
한 줄에 들어가는 한글은 12px 설명 기준으로 폭 100px 마다 약 8자다. 폭 200 상자의 설명은 한 줄에 16자 안팎이다. 줄은 단어 사이에서만 바뀐다.

## 6. 움직임

영상의 움직임은 화려하지 않다. 규칙은 아래와 같다.

1. **한 번에 한 곳만 바뀐다.** 단계 카드 여럿이 있으면 하나씩 켜진다. 나머지는 그대로 있다(3:25 듣기 -> 생각하기 -> 말하기).
2. **같은 자리의 내용을 바꿔 보인다.** 새 그림을 띄우지 않고 값과 강조만 바꾼다. 탭을 넘겨도 판은 그대로다(12:49 ~ 14:09).
3. **흐름은 선 위의 점으로 보인다.** 점은 일정한 속도로 가고 상자 뒤도 같은 속도로 지난다(8:49 요청 점이 라우터를 지나 블록 풀로 간다).
4. **양은 칸과 막대로 보인다.** 칸이 차고 비고, 막대가 늘고 준다(8:49 KV 블록 71 -> 52, 16:29 용량 칸).
5. **숫자는 세면서 바뀐다.** 큰 숫자는 한 번에 바뀌지 않고 올라가거나 내려간다.
6. **상태는 색으로 바뀐다.** 기준을 넘으면 장미, 통과하면 청록이 된다. 모양은 그대로다.
7. **초점은 흐리기로 준다.** 볼 것만 밝고 나머지는 흐려진다(20:05 로드맵의 지금 단계, 10:21 요약 카드 셋이 차례로).
8. **배경 움직임은 작다.** 파형, 계속 흐르는 요청 점, 선 그래프의 출렁임은 작게 계속 돌고 주인공 움직임을 가리지 않는다.

박자는 아래가 읽기 좋았다.

| 항목 | 값 |
|---|---|
| 한 반복 | 12 ~ 20초 |
| 강조 하나가 머무는 시간 | 0.6 ~ 1.5초 |
| 숫자가 세는 시간 | 0.8 ~ 1.2초 |
| 점이 상자 사이를 가는 속도 | `speed` 0.3 ~ 0.5 |
| 끝의 멈춤 | 1.5 ~ 2.5초. 결과를 읽을 시간이다 |
