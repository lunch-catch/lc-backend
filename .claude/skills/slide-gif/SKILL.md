# 발표용 애니메이션 GIF 만들기

코드에서 사실을 읽어 장면 정의(spec JSON)를 쓰고, 엔진이 그 장면을 그려 GIF 와 MP4 로 녹화한다.
장면의 모양과 움직임은 엔진이 맡으므로 이 작업에서 쓰는 것은 spec 하나다.

인자: $ARGUMENTS

## 1. 분류와 주제를 정한다

첫 인자는 분류이고 나머지는 주제다. 둘 중 하나가 비어 있으면 묻고 멈춘다.

| 분류 | 장면 | 맞는 주제 |
|---|---|---|
| 설계 | 왼쪽에 계층 스택을 두고, 한 층을 오른쪽에 펼쳐 내부 모듈과 흐름을 보인다 | 도메인 하나의 내부 구조, 패키지 구성, 요청이 모듈을 지나는 길 |
| 워커 | 요청이 판정하는 자리를 거쳐 여러 갈래로 나뉘고, 갈래마다 대기열이 찬다. 아래에 판정 수식을 둔다 | 배정, 분배, 라우팅, 점수와 순서를 정하는 로직 |
| 오토스케일링 | 위에 제어 루프(지표 -> 계산 -> 실행), 가운데에 서버와 데이터, 아래에 단계별 소요 시간을 둔다 | 인프라 구성, 확장과 축소, 배포, 장애 대응 |
| 워크플로우 | 단계 카드가 차례로 켜지고 진행 바가 찬다. 위에 그 단계를 감싸는 운영 루프를 둔다 | 배치 단계, 상태 전이, 명세에서 배포까지 같은 순서가 있는 과정 |

분류마다 배치 규칙과 움직임은 [reference/categories.md](reference/categories.md) 가 갖는다.

## 2. 엔진을 준비한다

처음 한 번만 한다. Node 18 이상이 있어야 한다.

```bash
cd .claude/skills/slide-gif/engine
npm install
npx playwright install chromium
```

ffmpeg 는 `npm install` 이 함께 받는다. 받지 못한 환경이면 시스템의 ffmpeg 를 쓴다.

## 3. 코드를 읽고 사실을 모은다

장면에 넣는 이름, 숫자, 순서는 모두 코드나 문서에서 가져온다. 추측한 값을 넣지 않는다.
어디를 읽을지는 [reference/sources.md](reference/sources.md) 가 정한다.

읽은 뒤 아래를 짧게 정리해 사용자에게 먼저 보인다. 사용자가 고치라고 하면 고친 뒤 진행한다.

- 제목 한 문장. 슬라이드가 말하려는 결론을 `~합니다.` 로 끝낸다
- 등장하는 상자와 각 상자의 한 줄 설명
- 움직임의 순서. 무엇이 어디서 어디로 가고 무엇이 켜지는지
- 근거 파일 목록

## 4. spec 을 쓴다

결과물은 저장소 루트의 `.slides/` 에 둔다. 파일 이름은 주제에서 공백을 `-` 로 바꾼 것이다. `11시 선착순 쿠폰 발급` 이면 `11시-선착순-쿠폰-발급` 이다.
아래 명령의 `{이름}` 이 그 값이다.

`examples/{분류}.json` 을 복사해 `.slides/{이름}.json` 으로 두고 고친다. 처음부터 쓰지 않는다.
예시는 좌표와 크기가 이미 맞춰져 있어서 상자 수와 글자만 바꾸면 겹침이 적다.
필드와 단계의 뜻은 [reference/spec.md](reference/spec.md) 가 갖는다.

`sources` 에 근거 파일을 적는다. 발표 뒤에 숫자를 물으면 이 목록으로 되짚는다.

## 5. 정지 화면으로 확인한다

저장소 루트에서 돌린다. `E` 는 엔진 폴더다.

```bash
E=.claude/skills/slide-gif/engine
node $E/build.js .slides/{이름}.json .slides/{이름}.html
node $E/record.js .slides/{이름}.html .slides/{이름}-a --still 1000
node $E/record.js .slides/{이름}.html .slides/{이름}-b --still {주인공 움직임이 한창인 시각}
node $E/record.js .slides/{이름}.html .slides/{이름}-c --still {loop 에서 2000 을 뺀 값}
```

`build.js` 가 경고를 내면 먼저 고친다. 그다음 PNG 세 장을 직접 열어 본다. 첫 장은 시작, 둘째는 가장 붐비는 순간, 셋째는 움직임이 끝난 결과다. 아래 중 하나라도 보이면 spec 을 고치고 다시 찍는다.

- 글자가 상자 밖으로 나가거나 잘린다
- 선이 상자를 가로지르거나 글자 위를 지난다
- 상자 안의 진행 바가 보이지 않는다. 상자 높이가 모자란 것이다
- 제목이 한 줄을 넘는다

## 6. 녹화한다

```bash
node $E/record.js .slides/{이름}.html .slides/{이름}
```

`{이름}.gif` 와 `{이름}.mp4` 가 나온다. 한 반복(`loop`)을 그대로 찍으므로 GIF 는 이음매 없이 돈다.
녹화는 브라우저 시계를 멈추고 프레임을 하나씩 넘겨서 컴퓨터가 느려도 끊기지 않는다.

끝나면 두 파일의 경로와 크기, 근거 파일 목록을 알린다. 발표 화면에는 MP4 가 더 선명하다는 것도 함께 알린다.

## 규칙

- 결과물은 `.slides/` 에 둔다. git 이 무시하는 경로라 저장소에 올라가지 않는다. `build/` 아래에 두면 `gradle clean` 이 지운다.
- 엔진(`engine/`)과 예시(`examples/`)를 바꾸는 것은 이 작업의 일이 아니다. 엔진이 표현하지 못하는 장면이면 무엇이 모자란지 알리고 멈춘다.
- 슬라이드 문장도 저장소의 문장 규칙(`AGENTS.md`)을 따른다. em dash 와 가운뎃점을 쓰지 않고 화살표는 `->` 로 쓴다.
- 속도가 빠르다는 말을 들으면 `speed` 를 낮추고 `loop` 를 늘린다. 점이 상자 뒤를 지날 때도 같은 속도로 움직이게 경로에 상자 가운데(`.c`)를 넣는다.
